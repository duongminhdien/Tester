1复习：进阶查询 – 上节课作业讲解

在进入新内容前，先回顾 Day 05 的10条复杂查询（employees + departments + salary 三表）。

已学核心技术要点

1GROUP BY + HAVING

先分组再过滤。HAVING 配合聚合函数（count、avg、sum）使用，不能用 WHERE 替代。

2多表联查 JOIN

连续 JOIN 多张表，每次 JOIN 都要写 ON 连接条件，缺一不可。

3子查询 Subquery

嵌套查询：放在 WHERE 中用于比较单值，放在 FROM 中充当临时表。

最复杂示例：查询工资低于本部门平均工资的员工

-- 第一步：计算各部门平均工资（子查询作为临时表） SELECT emp.deptid, avg(sa.salary) AS avg_salary FROM employees AS emp INNER JOIN salary AS sa ON sa.empid = emp.empid GROUP BY emp.deptid; -- 第二步：与临时表 JOIN，过滤 salary < avg_salary SELECT emp.empname, emp.deptid, sa.salary FROM employees AS emp INNER JOIN salary AS sa ON sa.empid = emp.empid INNER JOIN ( SELECT emp.deptid, avg(sa.salary) AS avg_salary FROM employees AS emp INNER JOIN salary AS sa ON sa.empid = emp.empid GROUP BY emp.deptid ) AS temp ON emp.deptid = temp.deptid WHERE sa.salary < temp.avg_salary;
💡 解题思路：把复杂问题拆成小步骤，分步编写、分步验证，最后嵌套组合。

4TPShop 数据库实战查询

2.1 – 查询商品分类信息（自关联）

-- 查看所有分类 SELECT * FROM tp_goods_category; -- 查看一级分类（parent_id = 0 表示顶级分类） SELECT * FROM tp_goods_category WHERE parent_id = 0; -- 查询"手机通讯"及其所有子分类（自关联） -- 第一步：找到"手机通讯"的 id SELECT id, name FROM tp_goods_category WHERE name = '手机通讯'; -- 第二步：自关联查询父分类 + 子分类 SELECT parent.name AS 父分类, child.name AS 子分类 FROM tp_goods_category AS parent INNER JOIN tp_goods_category AS child ON child.parent_id = parent.id WHERE parent.name = '手机通讯';

2.2 – 查询订单信息

-- 查看所有订单 SELECT * FROM tp_order; -- 查询 user_id=1 的订单及商品明细（联查两张表） SELECT o.order_sn AS 订单编号, o.order_status AS 订单状态, og.goods_name AS 商品名称, og.goods_price AS 商品单价, og.buy_count AS 购买数量 FROM tp_order AS o INNER JOIN tp_order_goods AS og ON og.order_id = o.order_id WHERE o.user_id = 1 ORDER BY o.order_id DESC;

2.3 – 查询购物车信息

-- 查询 user_id=1 的购物车，并计算小计金额 SELECT c.goods_name AS 商品名称, c.market_price AS 市场价, c.goods_price AS 会员价, c.goods_num AS 数量, (c.goods_price * c.goods_num) AS 小计 FROM tp_cart AS c WHERE c.user_id = 1;

3.1 + 3.2 – 修改用户数据

-- 修改用户昵称（qq字段）为 'test001' UPDATE tp_users SET qq = 'test001' WHERE user_id = 1; -- 修改用户积分（pay_points）为 20000 UPDATE tp_users SET pay_points = 20000 WHERE user_id = 1; -- 验证修改结果 SELECT user_id, email, qq, pay_points FROM tp_users WHERE user_id = 1;
⚠️ 高危警告：执行 UPDATE 时必须加 WHERE 条件！忘写 WHERE 将会修改整张表所有记录。正确姿势：先用 SELECT 确认目标记录，再改写为 UPDATE。

-- 为什么不能用 WHERE avg(salary)? -- 因为 WHERE 不能直接使用聚合函数！ -- avg() 需要先分组才能计算 → 必须先 GROUP BY → 只能用子查询 -- 第一步：计算各部门平均工资 SELECT deptid, AVG(salary) AS avg_salary FROM employees AS e JOIN salary AS s ON s.empid = e.empid GROUP BY deptid; -- → 结果：部门1001均薪3033，部门1002均薪3080... -- 第二步：将上述结果作为派生表（FROM中的子查询） SELECT e.empname, e.deptid, s.salary, temp.avg_salary FROM employees AS e JOIN salary AS s ON s.empid = e.empid JOIN ( SELECT deptid, AVG(salary) AS avg_salary FROM employees JOIN salary USING(empid) GROUP BY deptid ) AS temp ON e.deptid = temp.deptid WHERE s.salary < temp.avg_salary;

💬面试精讲 – 数据库设计与 SQL 查询（共12题）

涵盖数据库设计、实战查询技巧及测试人员在项目中的数据验证思路。

Q1
什么是自关联（自连接）？它的应用场景是什么？
基础
+

自关联是指一张表通过两个不同的别名与自身进行 JOIN 操作。适用于同一张表中存在父子层级关系的场景。

典型示例：tp_goods_category 中的 parent_id 指向同表的 id，一条记录可以同时扮演父节点和子节点的角色。

💡 固定写法：FROM table AS parent INNER JOIN table AS child ON child.parent_id = parent.id
Q2
内连接、左连接、右连接有什么区别？请举例说明。
基础
+

INNER JOIN（内连接）：只返回两张表中都有匹配记录的行（取交集）。若左表某行在右表无匹配，则该行被丢弃。

LEFT JOIN（左连接）：返回左表所有行，右表无匹配时用 NULL 填充。适用于"以左表为主，右表数据可选"的场景。

RIGHT JOIN（右连接）：与 LEFT JOIN 相反。实际开发中少用，通常通过调换表顺序改用 LEFT JOIN 替代。

示例：查询商品及其分类时，用 LEFT JOIN 可以保留尚未归类的商品（cat_id 为 NULL 的商品也会出现在结果中）。
Q3
UPDATE 不加 WHERE 会造成什么后果？
基础
+

不加 WHERE 的 UPDATE 会将表中所有行的指定字段全部更新，这是非常危险的操作，在生产环境中可能造成数据灾难。

示例：UPDATE tp_users SET pay_points = 0（无 WHERE）→ 所有用户积分清零。

⚠️ 最佳实践：先写 WHERE 条件，再用 SELECT 验证目标记录是否正确，最后将 SELECT 改写为 UPDATE。生产环境建议配合事务（Transaction）使用。
Q4
什么是外键（Foreign Key）？项目中一定要用外键约束吗？
基础
+

外键是一张表中指向另一张表主键的字段，用于保证引用完整性——不能插入在关联表中不存在的值。

一定要用吗？不是必须的。许多大型互联网公司（如 Facebook、Twitter）为了性能不在数据库层面使用外键，改为在应用层做数据校验。但对于初学者来说，外键是理解数据库关系设计的重要工具。

Q5
LNMP 架构中各组件分别负责什么？
基础
+

Linux – 服务器操作系统，稳定、安全、在 Web 服务器领域占主流地位。

Nginx（发音 Engine-X）– Web 服务器 / 反向代理，高并发性能优秀，负责处理静态资源和路由转发。

MySQL – 关系型数据库，存储和查询结构化数据。

PHP – 服务端脚本语言，处理业务逻辑，连接数据库并生成 HTML 返回给客户端。

Q6
子查询在 FROM 中和在 WHERE 中有什么区别？
进阶
+

WHERE 中的子查询：用于返回单一标量值进行比较。例如 WHERE salary > (SELECT avg(salary) FROM ...)。

FROM 中的子查询（派生表）：返回一个虚拟表，可以继续与其他表进行 JOIN。必须为其指定别名。例如 FROM (SELECT deptid, avg(salary) AS avg_salary ...) AS temp。

如何选择？需要单个值做比较 → 放在 WHERE 中。需要多行多列的临时结果集 → 放在 FROM 中作为派生表。
Q7
测试人员为什么需要掌握 SQL 和数据库结构？
基础
+

测试人员使用 SQL 的主要场景：

  • 验证测试数据：UI 操作完成后，查库确认数据是否正确落库
  • 准备测试数据：通过 SQL 快速构造测试前置条件（Test Data Setup）
  • 定位根因：Bug 出现时，通过查库排查是前端展示问题还是数据层问题
  • 数据一致性验证：确保 UI 展示值与数据库存储值完全一致
示例：测试"下单成功"后，查 tp_order 验证订单是否创建、user_id 是否正确、金额是否准确。

Q9
如何通过数据库验证"下单"功能是否正确？
进阶
+

UI + 数据库联合验证步骤：

  1. 登录 user_id=1 的账号，将商品加入购物车
  2. 查库验证：SELECT * FROM tp_cart WHERE user_id=1
  3. 完成下单操作
  4. 查库验证订单创建：SELECT * FROM tp_order WHERE user_id=1 ORDER BY order_id DESC LIMIT 1
  5. 验证订单商品明细：SELECT * FROM tp_order_goods WHERE order_id=?

Q10
GROUP BY 与 HAVING 和 WHERE 有什么区别？
进阶
+

WHERE：在分组之前过滤行，不能与聚合函数（COUNT、SUM、AVG...）一起使用。

GROUP BY：将具有相同列值的多行归为一组。

HAVING：在分组之后过滤分组，可以使用聚合函数。

SQL 执行顺序：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
Q11
实际开发中，什么时候用 LEFT JOIN 而不是 INNER JOIN？
高阶
+

当需要保留左表的全部记录（即使右表无对应数据）时，使用 LEFT JOIN，未匹配部分以 NULL 填充。

实际案例：统计每位用户的订单数量时，使用 LEFT JOIN 关联 tp_order：没有下过订单的用户也会出现在结果中，订单数显示为 0（配合 COALESCE 使用），而不是从结果集中消失。

选择依据：只需要两表都有匹配的数据 → INNER JOIN。需要保留主表所有记录、允许关联表为空 → LEFT JOIN。

✅测验 – 共15题

考察内容：TPShop 环境部署、数据库表设计、进阶 SQL 查询。

1TPShop 项目所使用的技术架构（LNMP）包含哪些组件？
✅ 正确答案：B – LNMP = Linux + Nginx + MySQL + PHP。TPShop 是 PHP 项目，使用 Nginx 作为 Web 服务器，MySQL 作为数据库。
2在 Linux 中，查看本机 IP 地址的命令是？
✅ 正确答案：B – ifconfig 是 CentOS 7 下查看网络接口信息的标准命令。ipconfig 是 Windows 的命令。
3tp_goods_category 表中，parent_id 字段指向同表的 id 字段，这种设计叫做什么？
✅ 正确答案：B – 自引用外键（Self-referencing FK）：外键指向本表自身的主键。常用于树形结构数据，如多级商品分类。
4查询 tp_goods_category 中一级分类（无上级节点），以下哪条语句正确？
✅ 正确答案：B – 根据 TPShop 的表结构设计，一级分类的 parent_id = 0（而非 NULL）。B 是最准确的写法。
5以下哪条语句能正确联查订单表与订单商品表？
✅ 正确答案：B – tp_order_goods.order_id 是指向 tp_order.order_id 的外键，通过它关联两张表才能获取某订单下的所有商品信息。
6以下哪条 UPDATE 语句存在严重风险？
✅ 正确答案：B – B 缺少 WHERE 条件，会将表中所有用户的 pay_points 都改为 20000！这是最常见也是最危险的 SQL 误操作之一。
7LEFT JOIN 与 INNER JOIN 的核心区别是什么？
✅ 正确答案：B – LEFT JOIN = 左表全部行 + 右表匹配行（不匹配则 NULL）。INNER JOIN = 只返回两表均有匹配的行。
8CentOS 上哪种安装方式需要连接互联网？
✅ 正确答案：C – yum 需要从软件仓库（repository）在线下载安装包及其依赖。rpm 和源码编译在有本地文件的情况下可以离线完成。
9查询 user_id = 1 的购物车总金额，以下哪条语句最准确？
✅ 正确答案：C – 总金额 = 每件商品的单价 × 数量，再求和。B 只累加了单价，忽略了数量，结果不正确。
10SQL 语句的正确执行顺序是？
✅ 正确答案：B – 执行顺序：FROM（确定数据源）→ WHERE（过滤行）→ GROUP BY（分组）→ HAVING（过滤分组）→ SELECT（选择字段）→ ORDER BY（排序）→ LIMIT（限制行数）。
11TPShop 中，用户昵称存储在 tp_users 表的哪个字段？
✅ 正确答案：C – 昵称存储在 qq 字段（TPShop 原版集成了 QQ 登录，故以此命名）。测试人员必须了解 UI 展示字段与数据库字段的对应关系。
12TPShop 中，用户积分存储在 tp_users 表的哪个字段？
✅ 正确答案：C – 积分存储在 pay_points 字段。本节课实战练习：UPDATE tp_users SET pay_points = 20000 WHERE user_id = 1。
13写在 FROM 子句中的子查询（派生表）有什么强制要求？
✅ 正确答案：B – FROM 中的子查询必须指定别名，否则 MySQL 会报语法错误。正确写法：FROM (SELECT ...) AS temp_name。
14执行 UPDATE 后，最恰当的验证方式是？
✅ 正确答案：B – 最佳验证方式：只查需要验证的字段，并通过 WHERE 精确定位目标记录。避免 SELECT * 全表查询——效率低且会暴露密码哈希等敏感信息。
15在生产数据库上执行 UPDATE 前，测试人员应该首先做什么？
✅ 正确答案：B – 标准操作流程：先用 SELECT * FROM table WHERE [条件] 确认目标记录无误 → 将 SELECT 改写为 UPDATE 执行。生产环境还应配合数据库备份（B 选项中的 C 也有价值，但 B 是必做的核心步骤）。
