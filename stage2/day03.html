1数据库简介

什么是数据库？

数据库 (Database) 指长期存储在计算机内、有组织的数据集合。简单说就是一个存储数据的仓库。

类比 Excel：数据库 = 整个 Excel 文件 · 数据表 = 文件中某个 Sheet · 数据行 = 表中一行记录 · 数据列 = 表中某个字段

数据库分类

🗂️ 关系型数据库

用表格方式存储，行列结构清晰，支持复杂查询和事务。代表：
  • Oracle — 大型项目（银行、电信）
  • MySQL — Web 项目最广泛 ⭐
  • SQL Server — 微软系项目
  • SQLite — 轻量级，移动端常用

🗃️ 非关系型数据库 (NoSQL)

用键-值对方式存储，灵活、性能高，但事务能力弱。代表：
  • Redis — 内存缓存，速度极快
  • MongoDB — 文档型，JSON 存储
  • HBase — 列存储，大数据场景

关系型 vs 非关系型 — 数据呈现方式

关系型（表格）：

idtitlepub_dateread
1射雕英雄传1980-05-0112
2天龙八部1986-07-2436
3笑傲江湖1995-12-2420

非关系型（键值对 JSON）：

{ "name": "mike", "age": 18, "city": "sz", "hobby": "study" }

数据约束 (重点)

约束 = 给字段加规则，保证数据合法。

primary key not null unique default foreign key auto_increment
约束含义用法
primary key主键 — 唯一标识，不能空、不能重复1 个表只能 1 个主键
auto_increment自动自增 — 通常配合主键使用在最大 ID 上 +1
not null非空 — 此字段不允许空值Null 和 '' 是不一样的
unique唯一 — 此字段不允许重复一个表可以有多个
default默认值 — 不填时使用填了以填的为准
foreign key外键 — 维护两表的关联关系如订单表的 user_id

6SQL 基础语句

建表语法

CREATE TABLE 表名( 字段名1 类型 约束, 字段名2 类型 约束, ...... );

建学生表示例（重要）

-- 姓名(长度10)、年龄、身高(保留2位小数) CREATE TABLE students( id int unsigned primary key auto_increment, -- id 主键自增 name varchar(20), -- 姓名 age int unsigned, -- 无符号整型 height decimal(5, 2) -- 5 位 (含 2 位小数) );

删表 / 添加数据 / 查询

-- 删表 DROP TABLE students; DROP TABLE IF EXISTS students; -- 不存在不会报错 -- 添加：全字段顺序写值（主键自增可用 0 或 null 代替） INSERT INTO students VALUES(0, '亚瑟', 22, 177.56); -- 添加：指定字段（适合不填所有字段） INSERT INTO students(name) VALUES('老夫子'); -- 查询全部 SELECT * FROM students;
🎯 SQL 注释：
• 单行：-- 注释（注意 -- 后面要有空格）
• 多行：/* 注释 */
• Navicat 快捷键：选中 → Ctrl + /

Q1关系型数据库和非关系型数据库的区别？基础+

关系型 (SQL)：

  • 用二维表存储数据，结构严格
  • 表与表之间用外键建立关联
  • 支持事务 (ACID)，数据一致性强
  • 用 SQL 查询，标准化程度高
  • 代表：MySQL, Oracle, SQL Server, SQLite

非关系型 (NoSQL)：

  • 结构灵活：键值对 / 文档 / 列族 / 图
  • 水平扩展能力强，适合大数据/高并发
  • 事务能力弱，最终一致性
  • 代表：Redis (KV), MongoDB (文档), HBase (列), Neo4j (图)

选型建议：核心业务数据用 MySQL；缓存/会话用 Redis；日志/海量文档用 MongoDB。

Q2SQL 分为哪几类？测试工程师最常用哪些？基础+

SQL 按用途分为 6 类：

  • DQL (Data Query) — 查询：select
  • DML (Data Manipulation) — 增改删：insert / update / delete
  • DDL (Data Definition) — 表结构：create / drop / alter
  • TPL (Transaction Processing) — 事务：begin / commit / rollback
  • DCL (Data Control) — 权限：grant / revoke
  • CCL (Cursor Control) — 游标：declare cursor

测试工程师重点掌握 DQL 和 DML：

  • 用 select 查数据验证 bug（前端显示金额 vs 数据库 amount 字段）
  • 用 insert/update 造测试数据（造满 1000 条订单测分页）
  • 用 delete 清理测试残留
Q3char 和 varchar 的区别？进阶+

char(N) — 定长：

  • 固定占 N 个字符空间，不足用空格补齐
  • 查询快，但浪费空间
  • 适合长度固定的字段：手机号、身份证、邮政编码

varchar(N) — 变长：

  • 实际占用 = 真实字符数 + 1~2 字节长度标识
  • 节省空间，但查询稍慢
  • 适合长度变化大的字段：姓名、地址、备注

实际选型：大多数业务字段用 varchar，只有手机号/身份证这种严格定长的才用 char。

Q4主键和唯一约束的区别？进阶+

主键 primary key：

  • 一个表只能有 1 个 主键
  • 必须唯一 + 非空，两个条件同时满足
  • 会自动创建聚簇索引（影响物理存储顺序）
  • 常配合 auto_increment 使用

唯一约束 unique：

  • 一个表可以有多个 unique 字段
  • 必须唯一，但可以为 NULL
  • 会创建普通索引

典型场景：用户表 id 是主键；手机号、邮箱是 unique。

Q5NULL 和 '' 空字符串有什么区别？陷阱+

NULL：未知 / 不存在。表示"这个字段还没填"。

''：空字符串。表示"这个字段填了，但内容是空"。

关键差异：

  • NULL 参与任何运算结果都是 NULL：NULL + 1 = NULL，NULL = NULL 返回 NULL（不是 true）
  • 判空必须用 IS NULL / IS NOT NULL，不能用 = NULL
  • NULL 不占空间或占很少（取决于存储引擎），'' 占 0~1 字节
  • COUNT(字段) 不统计 NULL，COUNT(*) 全统计

测试陷阱：查询时遗漏 NULL 处理是常见 bug 来源。比如 WHERE name != '张三' 不会返回 name 为 NULL 的记录。

Q6DROP / DELETE / TRUNCATE 的区别？陷阱+

DROP TABLE：

  • 删除整张表（结构 + 数据 + 索引 + 约束）
  • DDL 语句，不能回滚
  • 速度最快

DELETE FROM：

  • 只删行数据，表结构保留
  • DML 语句，可以回滚（事务内）
  • 可加 WHERE 删部分行
  • 慢，会逐行删除并写日志
  • 自增主键不重置

TRUNCATE TABLE：

  • 清空表数据，表结构保留
  • DDL 语句，不能回滚
  • 不能加 WHERE，要么全清要么不清
  • 速度快
  • 自增主键重置为 1

记忆口诀：DROP 拆房子，DELETE 一个个搬走，TRUNCATE 整层倒空。

Q7建表时主键的设计原则？进阶+

推荐做法：

  • 用独立的 id 字段作主键（不要用业务字段如手机号）
  • 类型选 int unsigned 或 bigint unsigned
  • 配合 auto_increment 自动自增
  • 不需要业务含义

为什么不用业务字段当主键？

  • 手机号会换、邮箱可改、身份证可能重号 → 不稳定
  • 业务字段一般是字符串，索引效率不如整型
  • 主键变更代价极大（外键、索引都要重建）

分布式场景：用 bigint + 雪花算法 (Snowflake) 或 UUID，避免分表后主键冲突。

Q8测试工程师拿到一个新数据库，怎么快速了解结构？场景+

命令行三连：

  1. show databases; — 看有哪些库
  2. use 库名; show tables; — 看库里有哪些表
  3. desc 表名; — 看每张表的字段结构
  4. show create table 表名; — 看完整建表语句（含索引、约束）

Navicat 工具流：

  1. 左侧树状视图直接展开库 → 表 → 字段
  2. 右击表 → 设计表 → 看字段、索引、外键
  3. 右击库 → 逆向数据库到模型 → 自动生成 ER 图

测试入项第一天必做：跑遍所有表 ER 图，理解业务实体关系。

Q9什么是字符集？为什么建库都用 utf8？进阶+

字符集 (charset)：规定字符如何映射到二进制存储。

常见字符集：

  • utf8 — Unicode 编码，3 字节，支持绝大部分语言（实际是 MySQL 的「3 字节 UTF-8」）
  • utf8mb4 — 4 字节真正的 UTF-8，支持emoji 表情和生僻汉字 ⭐推荐
  • gbk / gb2312 — 国标编码，2 字节，只支持中英文
  • latin1 — 西欧编码，1 字节，不支持中文

测试陷阱：

  • 建库时漏写 charset=utf8 → 默认 latin1 → 中文存进去乱码或报错
  • 有 emoji 的字段（评论、昵称）必须用 utf8mb4，不然存「😀」会报错

新项目最佳实践：CREATE DATABASE x CHARSET=utf8mb4;

Q10数据库备份有哪些方式？进阶+

1) Navicat 导出 SQL（手动）：

  • 右击库 → 转储 SQL 文件 → 结构和数据
  • 生成 .sql 文件，可用文本编辑器查看
  • 适合开发自测、迁移环境

2) 命令行 mysqldump（自动）：

  • mysqldump -uroot -p 库名 > backup.sql
  • 可定时任务 (crontab) 自动备份
  • 生产环境标准做法

3) 物理备份：直接拷贝 MySQL 数据目录 (/var/lib/mysql)，但必须先停服务，运维场景。

还原：mysql -uroot -p 库名 < backup.sql（注意：库要先存在）。

Q113306 端口是什么？为什么远程连不上？场景+

3306 是 MySQL 默认监听端口，所有连接都走它。

远程连不上的常见原因排查：

  1. 服务没起：netstat -anptu | grep 3306 看 LISTEN 状态
  2. 防火墙拦了：firewall-cmd --add-port=3306/tcp --permanent && firewall-cmd --reload
  3. MySQL 只绑了 127.0.0.1：检查 /etc/my.cnf 的 bind-address，改成 0.0.0.0
  4. 用户没远程权限：GRANT ALL ON *.* TO 'root'@'%' IDENTIFIED BY '密码';
  5. 云服务器安全组没开 3306

按这个顺序排查 90% 问题能解决。

Q12SELECT * 有什么问题？为什么不推荐？陷阱+

SELECT * 表示查询所有字段，看起来方便，实际有多个问题：

  • 性能差 — 把不需要的大字段（如 description、content）也查出来，浪费网络带宽和内存
  • 无法利用覆盖索引 — 索引只覆盖部分字段时，* 会强制回表查询
  • 表结构变更敏感 — 加字段会改变返回的列顺序，代码可能炸
  • 不清晰 — 看代码时不知道实际用了哪些字段

推荐写法：SELECT id, name, age FROM users WHERE id = 1; — 只查需要的字段。

学习/测试时用 SELECT * 探索数据无妨，但生产代码必须列字段名。
