1连接查询概述

在关系型数据库中，数据通常分散在多个表中。连接查询（JOIN）用于将多个表的数据组合在一起，根据表之间的关联关系查询出我们需要的结果。

连接类型 说明 关键字 特点
内连接 查询两个表的交集数据 INNER JOIN 只返回匹配的记录
左连接 左表全部 + 右表匹配部分 LEFT JOIN 右表不匹配用 NULL 填充
右连接 右表全部 + 左表匹配部分 RIGHT JOIN 左表不匹配用 NULL 填充
💡 记忆技巧
• 内连接 = 取交集（只要共同部分）
• 左连接 = 左表为主（左表全要，右表配合）
• 右连接 = 右表为主（右表全要，左表配合）

2内连接 INNER JOIN

内连接返回两个表中满足连接条件的记录，即两个表都存在的数据。

语法格式

SELECT * FROM 表1 INNER JOIN 表2 ON 表1.列 = 表2.列; -- 可以使用别名简化 SELECT * FROM students AS stu INNER JOIN scores AS sc ON stu.studentNo = sc.studentNo;

实战示例

-- 查询学生信息及成绩 SELECT stu.name, stu.age, sc.courseNo, sc.score FROM students stu INNER JOIN scores sc ON stu.studentNo = sc.studentNo; -- 连接三个表：学生+成绩+课程 SELECT stu.name, co.name AS course_name, sc.score FROM students stu INNER JOIN scores sc ON stu.studentNo = sc.studentNo INNER JOIN courses co ON sc.courseNo = co.courseNo;
⚠️ 注意事项
• 表的别名可以省略 AS 关键字
• ON 后面指定的是连接条件（通常是外键关系）
• 可以连接多个表，但要注意性能问题
• WHERE 条件在 ON 之后添加

3左连接 LEFT JOIN

左连接返回左表的所有记录，即使右表中没有匹配的记录。右表中不存在的数据用 NULL 填充。

语法格式

SELECT * FROM 表1 LEFT JOIN 表2 ON 表1.列 = 表2.列;

实战示例

-- 查询所有学生的成绩，包括没有成绩的学生 SELECT stu.name, sc.courseNo, sc.score FROM students stu LEFT JOIN scores sc ON stu.studentNo = sc.studentNo; -- 结果：所有学生都会显示，没有成绩的学生 score 字段为 NULL
✅ 使用场景
• 统计所有部门的员工数量（包括没有员工的部门）
• 查询所有课程的选课情况（包括没人选的课程）
• 查找数据缺失的情况（WHERE 右表字段 IS NULL）

4右连接 RIGHT JOIN

右连接返回右表的所有记录，即使左表中没有匹配的记录。左表中不存在的数据用 NULL 填充。

-- 查询所有课程的学生成绩，包括没有学生选的课程 SELECT co.name AS course_name, stu.name, sc.score FROM scores sc RIGHT JOIN courses co ON sc.courseNo = co.courseNo LEFT JOIN students stu ON sc.studentNo = stu.studentNo;
💡 提示
右连接可以改写成左连接，只需交换表的位置即可。实际开发中，左连接使用更频繁。

5自关联

自关联是指同一张表与自己进行连接查询。通常用于表中存在层级关系的场景。

应用场景

1地区表

省、市、区在同一张表中，通过 pid 字段关联

2分类表

一级分类、二级分类在同一张表

3组织架构

员工表中包含上级领导 ID

示例：地区表

-- 表结构：areas(aid, atitle, pid) -- aid=130000, atitle='河北省', pid=NULL -- aid=130100, atitle='石家庄市', pid=130000 -- 查询河北省下的所有城市 SELECT a2.aid, a2.atitle AS city_name FROM areas AS a1 INNER JOIN areas AS a2 ON a1.aid = a2.pid WHERE a1.atitle = '河北省';
⚠️ 重点
自关联必须使用别名，否则数据库无法区分是哪个表的字段。

6子查询

子查询是指将一个 SELECT 查询嵌套在另一个 SQL 语句中。子查询可以充当条件或数据源。

1. 子查询充当条件

-- 标量子查询（返回单个值） SELECT * FROM students WHERE age > (SELECT AVG(age) FROM students); -- 列子查询（返回一列） SELECT score FROM scores WHERE studentNo IN ( SELECT studentNo FROM students WHERE age = 18 ); -- 行子查询（返回一行多列） SELECT * FROM students WHERE (class, age) = ( SELECT class, age FROM students WHERE name = '王昭君' );

2. 子查询充当数据源

-- 表子查询：子查询结果作为临时表 SELECT * FROM scores AS sc INNER JOIN ( SELECT * FROM courses WHERE name IN ('数据库', '系统测试') ) AS co ON sc.courseNo = co.courseNo;

特定关键字

关键字 说明 等价于
IN 在...之中 = ANY
ANY 任意一个 IN
SOME ANY的别名 IN / ANY
NOT IN 不在...之中 != ALL
ALL 所有 与 != 组合等于 NOT IN
📌 子查询优化建议
• 简单情况优先使用 JOIN 而非子查询（性能更好）
• 避免在 WHERE 中使用相关子查询（每行都执行一次）
• 子查询结果集较大时，考虑建立临时表
• 使用 EXISTS 代替 IN（当子查询数据量大时）

WHERE score > 80

🔍JOIN vs 子查询性能对比

场景 推荐方式 原因
简单的多表关联 JOIN 性能更好，优化器可以优化执行计划
需要聚合函数结果作为条件 子查询 逻辑更清晰，易于理解
EXISTS 判断存在性 子查询 + EXISTS 找到第一条就停止，效率高
IN 大量数据 JOIN 避免 IN 子查询的性能问题
💡 优化建议
• 小数据集（< 1000行）：两者性能差异不大
• 大数据集：优先使用 JOIN，避免相关子查询
• 使用 EXPLAIN 分析执行计划，选择更优方案

💬面试精讲

掌握连接查询、自关联和子查询的常见面试问题。

Q1
什么是内连接？它与外连接有什么区别？
基础
+

内连接（INNER JOIN）：只返回两个表中满足连接条件的记录，即两个表的交集。

外连接：包括左连接（LEFT JOIN）和右连接（RIGHT JOIN），除了返回匹配的记录外，还会返回某一侧表的所有记录，不匹配的部分用 NULL 填充。

区别：

  • 内连接：只要交集
  • 左连接：左表全要 + 交集
  • 右连接：右表全要 + 交集
Q2
什么场景下需要使用自关联？
基础
+

自关联用于同一张表内存在层级关系或上下级关系的场景：

  • 地区表：省、市、区在同一张表，通过 pid 关联
  • 员工表：员工与上级领导在同一张表
  • 分类表：一级分类、二级分类在同一张表
  • 评论表：评论与回复在同一张表

要点：必须使用别名区分同一张表的不同角色。

Q3
子查询有哪几种类型？
基础
+

按返回结果分类：

  • 标量子查询：返回单个值（如 AVG、MAX、COUNT）
  • 列子查询：返回一列多行（常与 IN、ANY、ALL 配合）
  • 行子查询：返回一行多列（与多个字段同时比较）
  • 表子查询：返回多行多列（作为临时表使用）

按位置分类：

  • WHERE 子查询：作为条件
  • FROM 子查询：作为数据源
  • SELECT 子查询：作为查询字段（少用）
Q4
LEFT JOIN 和 RIGHT JOIN 可以互相转换吗？
进阶
+

可以！只需交换表的位置即可：

-- 这两条 SQL 结果相同 SELECT * FROM students LEFT JOIN scores ON ... SELECT * FROM scores RIGHT JOIN students ON ...

实际开发建议：优先使用 LEFT JOIN，代码可读性更好，团队统一标准。

Q5
如何找出没有成绩的学生？
进阶
+

使用 LEFT JOIN + IS NULL 组合：

SELECT st.sno, st.sname FROM students st LEFT JOIN scores sc ON st.sno = sc.sno WHERE sc.sno IS NULL;

原理：左连接会保留左表所有数据，没有成绩的学生在右表字段为 NULL。

Q6
IN 和 EXISTS 有什么区别？
进阶
+
对比项 IN EXISTS
执行方式 先执行子查询，返回完整结果集 逐行判断，找到即停止
适用场景 子查询数据量小 子查询数据量大
性能 子查询大时慢 短路机制，效率高
-- IN：查询选过课的学生 SELECT * FROM students WHERE sno IN (SELECT sno FROM scores); -- EXISTS：同样功能，大数据时更快 SELECT * FROM students st WHERE EXISTS (SELECT 1 FROM scores sc WHERE sc.sno = st.sno);
Q7
多表 JOIN 时，ON 和 WHERE 的区别是什么？
陷阱
+

核心区别：执行时机不同！

  • ON：在连接时过滤（先过滤再连接）
  • WHERE：在连接后过滤（先连接再过滤）

对 INNER JOIN：两者效果相同

对 LEFT/RIGHT JOIN：ON 影响右表，WHERE 影响结果集

-- 这两条 SQL 在 LEFT JOIN 时结果不同！ SELECT * FROM students st LEFT JOIN scores sc ON st.sno=sc.sno AND sc.score>80; -- 结果：所有学生都显示，分数≤80的成绩字段为NULL SELECT * FROM students st LEFT JOIN scores sc ON st.sno=sc.sno WHERE sc.score>80; -- 结果：只显示分数>80的学生（没有成绩的学生被过滤）
Q8
如何优化包含子查询的慢查询？
场景
+

优化策略：

  • 用 JOIN 替代子查询：大部分情况下 JOIN 性能更好
  • 避免相关子查询：每行都执行一次，性能极差
  • 使用 EXISTS 替代 IN：子查询数据量大时
  • 建立索引：子查询关联字段加索引
  • 使用临时表：复杂子查询先存临时表
-- ❌ 慢：相关子查询（每行执行一次） SELECT * FROM students st WHERE (SELECT COUNT(*) FROM scores sc WHERE sc.sno=st.sno) > 5; -- ✅ 快：改用 JOIN + GROUP BY SELECT st.* FROM students st INNER JOIN scores sc ON st.sno=sc.sno GROUP BY st.sno HAVING COUNT(*) > 5;
Q9
如何查询选修了全部课程的学生？
进阶
+

方法1：分组统计 + 子查询

SELECT st.sno, st.sname FROM students st INNER JOIN scores sc ON st.sno = sc.sno GROUP BY st.sno, st.sname HAVING COUNT(DISTINCT sc.cno) = (SELECT COUNT(*) FROM courses);

方法2：双重否定（没有他没选的课）

SELECT * FROM students st WHERE NOT EXISTS ( SELECT * FROM courses co WHERE NOT EXISTS ( SELECT * FROM scores sc WHERE sc.sno=st.sno AND sc.cno=co.cno ) );
Q10
ANY、ALL、SOME 的区别是什么？
基础
+
关键字 含义 等价
= ANY 等于任意一个 IN
!= ALL 不等于所有 NOT IN
SOME ANY 的别名 ANY
> ANY 大于最小值 > MIN()
> ALL 大于最大值 > MAX()
-- 查询比任意一个男生年龄大的女生 SELECT * FROM students WHERE sex='女' AND age > ANY(SELECT age FROM students WHERE sex='男');
Q11
如何实现排名查询（每个班级成绩前3名）？
场景
+

MySQL 8.0+ 使用窗口函数：

SELECT * FROM ( SELECT st.class, st.sname, sc.score, ROW_NUMBER() OVER(PARTITION BY st.class ORDER BY sc.score DESC) AS rank FROM students st INNER JOIN scores sc ON st.sno = sc.sno ) AS ranked WHERE rank <= 3;
Q12
UNION 和 JOIN 有什么区别？
进阶
+
对比项 JOIN UNION
方向 横向合并（增加列） 纵向合并（增加行）
数据来源 多个表 多个查询结果
列数要求 无要求 列数必须相同
去重 不去重 UNION去重，UNION ALL不去重
