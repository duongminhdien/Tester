1数据更新操作 (DML)

添加多行数据

方式一：写多条 INSERT 语句（每条用分号分隔）

方式二：一条 INSERT 插入多行（VALUES 之间用逗号分隔）— 推荐，性能更好

-- 方式一: 多条 SQL INSERT INTO students(id, name) VALUES(0, '张三'); INSERT INTO students(id, name) VALUES(0, '李四'); -- 方式二: 一条 SQL 多行 (推荐!) INSERT INTO students VALUES (0, '亚瑟3', 23, 167.56), (0, '亚瑟4', 23, 167.56); -- 部分字段多行 INSERT INTO students(id, name) VALUES (0, '小乔'), (0, '小红'), (null, '大白');
💡 性能对比：插入 1000 条数据，方式二比方式一快 5~10 倍，因为只走一次解析、一次事务提交。

修改数据 (UPDATE)

-- 格式: UPDATE 表 SET 字段=值, 字段=值 WHERE 条件 UPDATE students SET name='狄仁杰', age=22 WHERE id=5;
⚠️ 致命陷阱：UPDATE 必须加 WHERE 条件！不加的话全表所有行都会被修改，是新手最常翻车的地方。生产事故 #1。

删除数据 — 3 种方式对比

DELETE FROM
  • 删除指定行
  • 可加 WHERE
  • 可回滚（事务内）
  • 自增 id 不重置
  • 速度慢
TRUNCATE TABLE
  • 清空所有行
  • 表结构保留
  • 不能回滚
  • 自增 id 从 1 重置
  • 速度快
DROP TABLE
  • 删除整张表
  • 结构 + 数据全删
  • 不能回滚
  • 速度最快
  • 慎用！
DELETE FROM students WHERE id=6; -- 物理删除一行 TRUNCATE TABLE students; -- 清空表 DROP TABLE students; -- 删除整张表
🎯 工作实践 — 逻辑删除：实际项目中很少物理删除，而是用 is_delete 字段标记（1=已删, 0=未删）。这样可恢复，也能审计。

2查询基础操作

查询部分字段

-- 只查需要的字段, 比 SELECT * 性能好 SELECT name, sex, age FROM students;

起别名（AS）

给表或字段起别名，让 SQL 更易读：

-- 给表起别名 (为后面多表关联做准备) SELECT s.name, s.sex FROM students AS s; -- 给字段起别名 (显示更友好) SELECT name AS 姓名, sex AS 性别 FROM students;
注意：AS 可以省略，SELECT name 姓名 FROM students 也能用，但加上 AS 更清晰，推荐保留。

去重（DISTINCT）

-- 查询去重后的性别 SELECT DISTINCT sex FROM students; -- 结果只有: 男 / 女 两行 -- 多字段联合去重 SELECT DISTINCT class, sex FROM students;

3条件查询 (WHERE) — 6 种方式

① 比较运算符

> >= < <= = != / <>
SELECT * FROM students WHERE age < 20; SELECT name FROM students WHERE hometown != '北京';

② 逻辑运算符

AND OR NOT
-- AND: 同时满足两个条件 SELECT * FROM students WHERE age=18 AND sex='女'; -- OR: 满足其中一个条件即可 SELECT * FROM students WHERE sex='女' OR class='1班'; -- NOT: 不满足条件 SELECT * FROM students WHERE NOT age=20;

③ 模糊查询 (LIKE)

通配符：% 匹配任意个字符 · _ 匹配一个字符

-- 姓孙的学生 (孙开头, 后面任意) SELECT * FROM students WHERE name LIKE '孙%'; -- 名字以"乔"结尾 SELECT * FROM students WHERE name LIKE '%乔'; -- 名字中含有"白" SELECT * FROM students WHERE name LIKE '%白%'; -- 名字是两个字的 SELECT * FROM students WHERE name LIKE '__'; -- 姓孙且名字只有两个字 (孙 + 一个字) SELECT * FROM students WHERE name LIKE '孙_';

④ 范围查询 (IN / BETWEEN AND)

-- IN: 在指定枚举值内 (非连续) SELECT * FROM students WHERE hometown IN('北京', '上海', '广东'); -- 等价于 SELECT * FROM students WHERE hometown='北京' OR hometown='上海' OR hometown='广东'; -- BETWEEN AND: 连续范围 (包含端点!) SELECT * FROM students WHERE age BETWEEN 18 AND 20; -- 等价于 SELECT * FROM students WHERE age >= 18 AND age <= 20; -- NOT IN / NOT BETWEEN SELECT * FROM students WHERE age NOT BETWEEN 20 AND 25;

⑤ 空判断 (IS NULL)

-- ⚠️ NULL 必须用 IS, 不能用 = SELECT * FROM students WHERE card IS NULL; SELECT * FROM students WHERE card IS NOT NULL; -- ❌ 错误写法: WHERE card = NULL → 永远返回 0 行
⚠️ 经典陷阱：NULL 不等于任何值（包括 NULL 自己）。card = NULL 和 card != NULL 都返回 0 行！必须用 IS NULL。

4排序 (ORDER BY)

语法：SELECT ... FROM 表 ORDER BY 字段1 [ASC|DESC], 字段2 [ASC|DESC]...

ASC ↑

升序 (从小到大) — 默认，可省略

DESC ↓

降序 (从大到小)
-- 按年龄升序 SELECT * FROM students ORDER BY age; -- 多字段排序: 先按年龄降序, 年龄相同再按学号升序 SELECT * FROM students ORDER BY age DESC, studentNo ASC;

5聚合函数 — 5 大神器

聚合函数对一组数据进行统计计算，返回单个值。

🔢
COUNT(*)
统计总记录数
🏔️
MAX(字段)
最大值
🏖️
MIN(字段)
最小值
➕
SUM(字段)
求和
📊
AVG(字段)
平均值
-- 统计学生总数 SELECT COUNT(*) FROM students; -- 女生的最大年龄 SELECT MAX(age) FROM students WHERE sex='女'; -- 1 班的最小年龄 SELECT MIN(age) FROM students WHERE class='1班'; -- 北京学生的年龄总和 SELECT SUM(age) FROM students WHERE hometown='北京'; -- 女生平均年龄 SELECT AVG(age) FROM students WHERE sex='女';
⚠️ 关键差异：
• COUNT(*) — 统计所有行（包括 NULL）
• COUNT(字段) — 不统计 NULL 值
• AVG/SUM — 自动跳过 NULL

6分组查询 (GROUP BY) + HAVING

分组查询

语法：SELECT 字段1, 字段2, 聚合函数 FROM 表 GROUP BY 字段1, 字段2...

-- 按性别分组, 统计每种性别的人数 SELECT sex, COUNT(*) FROM students GROUP BY sex; -- 结果: -- 女 | 5 -- 男 | 7 -- 每种性别的最大年龄 SELECT sex, MAX(age) FROM students GROUP BY sex; -- 多字段分组: 先按班级, 再按性别 SELECT class, sex, COUNT(*) FROM students GROUP BY class, sex;

HAVING — 分组后筛选

分组后想再过滤，用 HAVING（不能用 WHERE）：

-- ❌ 错误: WHERE 不能用聚合函数 -- SELECT class, COUNT(*) FROM students WHERE COUNT(*) > 3 GROUP BY class; -- ✅ 正确: 用 HAVING SELECT class, COUNT(*) FROM students GROUP BY class HAVING COUNT(*) > 3; -- 查询每个班级中男女人数 > 1 的 SELECT class, sex, COUNT(*) FROM students GROUP BY class, sex HAVING COUNT(*) > 1;
🎯 WHERE vs HAVING：
• WHERE — 对原始数据筛选，在分组之前执行，不能用聚合函数
• HAVING — 对分组结果筛选，在分组之后执行，可以用聚合函数

7分页查询 (LIMIT)

语法：SELECT * FROM 表 LIMIT 起点, 数量

起点从 0 开始（不是 1！），表示跳过几行。

-- 查询前 3 行 (起点 0, 取 3 条) SELECT * FROM students LIMIT 0, 3; SELECT * FROM students LIMIT 3; -- 简写 -- 第 2~6 条 (跳过 1 条, 取 5 条) SELECT * FROM students LIMIT 1, 5; -- 第 11~12 条 (跳过 10 条, 取 5 条, 但只剩 2 条) SELECT * FROM students LIMIT 10, 5;

分页公式（必背！）

第 n 页，每页 m 条：LIMIT (n-1)*m, m

页数 n每页 mSQL结果
15LIMIT 0, 5第 1~5 条
25LIMIT 5, 5第 6~10 条
35LIMIT 10, 5第 11~15 条
📐 总页数公式：总记录数 ÷ 每页数（除不尽 +1）。如 12 条记录每页 5 个 → 12÷5=2 余 2 → 3 页。

⚡理论题 (4 题)

1. DELETE 和 DROP 删除命令有什么区别？
▸ 查看答案
DELETE FROM 表 WHERE ... - 删除行数据, 表结构保留 - 可加 WHERE 删部分行 - 是 DML 语句, 可以回滚 (事务内) - 自增 id 不重置 - 速度慢 (逐行删 + 写日志) DROP TABLE 表 - 删除整张表 (结构 + 数据 + 索引) - 不能加 WHERE - 是 DDL 语句, 不能回滚 - 速度最快 # 补充: TRUNCATE TABLE 表 - 清空表数据, 表结构保留 - 不能加 WHERE, 不能回滚 - 自增 id 重置为 1
2. WHERE 条件查询有哪几种方式？
▸ 查看答案
六大方式: 1) 比较: =, !=, <>, >, <, >=, <= 2) 逻辑: AND, OR, NOT 3) 模糊: LIKE '%' (任意字符) / '_' (一个字符) 4) 范围: IN (1, 2, 3) -- 非连续枚举 BETWEEN x AND y -- 连续范围 (含端点) 5) 空判断: IS NULL / IS NOT NULL 6) 否定: NOT IN / NOT BETWEEN / NOT LIKE
3. MySQL 中常用的聚合函数有哪些？
▸ 查看答案
5 大聚合函数: COUNT(字段) -- 统计记录数 COUNT(*) 算所有行 COUNT(字段) 跳过 NULL MAX(字段) -- 最大值 MIN(字段) -- 最小值 SUM(字段) -- 求和 (NULL 跳过) AVG(字段) -- 平均 (NULL 跳过) # 注意: - 聚合函数 不能在 WHERE 用, 要用 HAVING - 多用于 GROUP BY 分组统计
4. 起别名用什么命令？可以给什么起别名？注意点？
▸ 查看答案
命令: AS (可以省略) # 给表起别名 (主要为多表 JOIN 用) SELECT s.name FROM students AS s; SELECT s.name FROM students s; -- AS 可省 # 给字段起别名 (显示更友好) SELECT name AS 姓名 FROM students; SELECT name 姓名 FROM students; -- AS 可省 注意点: 1) 别名只在当前 SELECT 内有效 2) ORDER BY 可以用别名, WHERE 不能用 (执行顺序: WHERE → GROUP → SELECT → ORDER) 3) 含空格/特殊字符的别名要加反引号: SELECT name AS `学生 姓名` FROM students; 4) 表别名很重要, 多表 JOIN 时减少歧义

💬高频面试题 (12 题)

点击题目展开答案。基础 进阶 陷阱/场景

Q1DELETE / TRUNCATE / DROP 三个删除命令有什么区别？基础+

DELETE FROM 表 [WHERE]：

  • DML 语句，可以回滚（事务内）
  • 可加 WHERE 删部分行
  • 速度慢（逐行删 + 写日志）
  • 自增 id 不重置

TRUNCATE TABLE 表：

  • DDL 语句，不能回滚
  • 不能加 WHERE，只能整张表清空
  • 速度快
  • 自增 id 重置为 1

DROP TABLE 表：

  • DDL，不能回滚
  • 结构 + 数据 + 索引全删
  • 速度最快

记忆口诀：DELETE 一个个搬走（可挽回），TRUNCATE 整层倒空（重置），DROP 拆房子（连地基都没）。

Q2UPDATE 不加 WHERE 会怎样？怎么预防？陷阱+

会导致全表所有行被修改！这是生产事故 Top 1。

比如：UPDATE users SET status = 'inactive'; 会让所有用户都变 inactive。

预防措施：

  1. 开启 safe update mode：MySQL 客户端运行 SET sql_safe_updates = 1; — 没 WHERE 的 UPDATE/DELETE 会被拒绝
  2. Navicat 在「工具→选项→自动事务」开启，可手动 commit / rollback
  3. 写之前先用 SELECT 验证：SELECT * FROM users WHERE id = 5 看返回行数对不对，再把 SELECT 改成 UPDATE
  4. 生产数据库操作前先备份

真实案例：某电商工程师把 UPDATE orders SET status='cancelled' WHERE id=1234 漏写 WHERE，1 秒内把 50w 订单全取消，损失百万。

Q3WHERE 和 HAVING 的区别？进阶+

WHERE：

  • 对原始数据过滤
  • 在 GROUP BY 之前执行
  • 不能用聚合函数
  • 用于筛选行

HAVING：

  • 对分组结果过滤
  • 在 GROUP BY 之后执行
  • 可以用聚合函数
  • 用于筛选分组

实例对比：

「查每个班人数 > 3 的班」：

SELECT class, COUNT(*) FROM students GROUP BY class HAVING COUNT(*) > 3

不能写成 WHERE COUNT(*) > 3，因为 WHERE 时还没分组，没有 COUNT 这个值。

Q4SQL 的执行顺序是什么？进阶+

书写顺序：SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT

执行顺序：

  1. FROM — 从哪张表
  2. WHERE — 行过滤
  3. GROUP BY — 分组
  4. HAVING — 分组后过滤
  5. SELECT — 挑字段（这里别名才生效）
  6. ORDER BY — 排序（可以用别名）
  7. LIMIT — 限制行数（最后）

为什么重要？知道了这个就能解释：

  • 为什么 WHERE 不能用别名？— 因为 SELECT 还没执行
  • 为什么 WHERE 不能用聚合函数？— 因为 GROUP BY 还没执行
  • 为什么 ORDER BY 可以用别名？— 因为 SELECT 已经执行完了
Q5LIKE 的通配符有哪些？怎么转义？进阶+

两个通配符：

  • % — 匹配任意个（0 个或多个）字符
  • _ — 匹配1 个字符

转义：如果要匹配字面的 % 或 _，用 ESCAPE：

SELECT * FROM products WHERE name LIKE '%50\%%' ESCAPE '\\' — 查名字包含 "50%" 的产品

性能陷阱：

  • LIKE 'abc%' — 前缀匹配，能用索引，快
  • LIKE '%abc' — 后缀匹配，不能用索引，慢
  • LIKE '%abc%' — 全模糊，全表扫描，超慢

大数据量场景下，全模糊匹配要换成 全文索引 (FULLTEXT) 或 ES 等搜索引擎。

Q6IN 和 BETWEEN AND 的区别？什么时候用哪个？基础+

IN：用于非连续的多个具体值。

WHERE hometown IN ('北京', '上海', '广东')

BETWEEN AND：用于连续的范围（包含端点）。

WHERE age BETWEEN 18 AND 25 等价于 age >= 18 AND age <= 25

关键差异：

  • BETWEEN 是闭区间（包含端点），新手常忘
  • BETWEEN 适合数值、日期类型；IN 适合字符串枚举
  • age BETWEEN 30 AND 18 返回 0 行（左大右小语义错误）

选哪个看场景：年龄段用 BETWEEN，城市列表用 IN。

Q7COUNT(*) / COUNT(字段) / COUNT(1) 有什么区别？陷阱+

COUNT(*)：

  • 统计所有行数（包括含 NULL 的行）
  • 性能最好，MySQL 引擎专门优化过
  • 推荐使用

COUNT(字段)：

  • 统计该字段不为 NULL 的行数
  • 会跳过 NULL 值
  • 性能稍差（要检查 NULL）

COUNT(1)：

  • 和 COUNT(*) 等价（统计所有行）
  • 本质上没差别，MySQL 都做了优化

典型坑：有 100 个用户，其中 10 个 phone 字段为 NULL。COUNT(*) 返回 100，COUNT(phone) 返回 90。如果想统计"有手机号的用户数"用 COUNT(phone) 就对了。

Q8分页查询大数据量时性能差怎么办？场景+

问题：LIMIT 1000000, 10 — MySQL 仍要扫描前 100w+10 行，然后丢弃前 100w 行，超慢。

优化方案：

  1. 覆盖索引 + 子查询：先用主键索引拿到 10 个 id，再 JOIN 回原表

    SELECT * FROM orders WHERE id IN (SELECT id FROM orders ORDER BY id LIMIT 1000000, 10)

  2. 记录上次 id：第二页起用 WHERE id > 上次最大id LIMIT 10

    SELECT * FROM orders WHERE id > 1000000 ORDER BY id LIMIT 10

  3. 禁止跳页：很多 APP 只能"下拉刷新"，不能跳到第 1000 页，从产品层规避
  4. 搜索引擎：用 ElasticSearch 做大数据量分页

面试常考，记一两种就够了。

Q9怎么取学生表第 2 高的年龄？陷阱+

方法 1：ORDER BY + LIMIT（最简单）

SELECT age FROM students ORDER BY age DESC LIMIT 1, 1

跳过 1 行（即最大值），取 1 行（即第 2 大）。

方法 2：DISTINCT 去重（处理重复年龄）

SELECT DISTINCT age FROM students ORDER BY age DESC LIMIT 1, 1

方法 3：子查询

SELECT MAX(age) FROM students WHERE age < (SELECT MAX(age) FROM students)

陷阱：如果有两个学生同年龄 30，方法 1 会跳过其中一个 30 当成"第二大"返回另一个 30，方法 2 才是真正的"第二大"。面试时一定要追问这个差异。

Q10SELECT 后能写 GROUP BY 之外的非聚合字段吗？陷阱+

SQL 标准：不能。SELECT 列表中的字段，要么是 GROUP BY 里的字段，要么是聚合函数包裹的字段。

错误示例：

SELECT class, name, COUNT(*) FROM students GROUP BY class

这里 name 不在 GROUP BY，也没用聚合函数 → 语义不清（一个班可能多个 name，到底返回哪个？）

MySQL 的"宽松"行为：低版本 MySQL 默认允许这种写法，会随机返回某一行的 name，结果不可预测。MySQL 5.7+ 默认开启 ONLY_FULL_GROUP_BY 模式，会直接报错。

测试场景：测试时如果 dev 环境用旧 MySQL 没问题，到生产环境（开启严格模式）就炸了，这是常见 bug 来源。

Q11测试工程师常用 SQL 工作场景举例？场景+

1) 验证 bug：前端显示订单金额 ¥199.5 但用户反馈实付了 ¥299.5。

SELECT id, amount, paid_amount FROM orders WHERE user_id = 12345 直接看数据库真实值。

2) 造测试数据：测分页要 100 条数据。

写 INSERT 循环或一次插入 100 行。

3) 验证业务逻辑：新用户 7 天没下单要触发短信。

SELECT COUNT(*) FROM users WHERE created_at < NOW() - INTERVAL 7 DAY AND id NOT IN (SELECT user_id FROM orders) 看是不是正确的数量。

4) 性能测试准备：清空测试库残留数据。

TRUNCATE TABLE test_orders

5) 复现线上问题：把生产某条数据复制到测试环境验证。

6) 接口测试断言：调完 API 后查数据库验证落库正确性。

Q12ORDER BY 字段为 NULL 时排在哪里？陷阱+

MySQL 默认：

  • ORDER BY x ASC — NULL 排最前面
  • ORDER BY x DESC — NULL 排最后面

记忆：把 NULL 当作最小值就对了（升序最小在前，降序最小在后）。

不同数据库不一样：

  • Oracle、PostgreSQL：默认 NULL 当最大值
  • SQL Server：可控制，ORDER BY x NULLS LAST

测试陷阱：本地用 MySQL 测，生产用 PostgreSQL，排序结果不一样 → bug。

MySQL 控制 NULL 位置的技巧：

ORDER BY x IS NULL, x ASC — NULL 放最后
