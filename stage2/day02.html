1文件操作命令

查看文件内容：cat / more / grep

命令用途常用选项
cat查看较少内容的文件；也可创建/合并/追加-n 显示所有行号
-b 非空行编号
more查看较多内容的文件，分页显示空格=下一页 / b=上一页 / f=下一页 / q=退出
grep搜索文件并显示关键字行-n 显示行号
-i 忽略大小写
-v 取反（不包含）
# cat: 查看 stdio.h 全部内容（带行号） $ cat -n /usr/include/stdio.h # more: 分页查看长文件 $ more /var/log/messages # grep: 搜索包含 vmware（忽略大小写）的行 $ grep -i 'vmware' /var/log/messages # grep 正则：以 a 开头的行 / 以 ke 结尾的行 $ grep '^a' 1.txt $ grep 'ke$' 1.txt # [Ss]igna[Ll] 匹配 Signal / signal / SignaL / signaL $ grep -n '[Ss]igna[Ll]' 1.txt

重定向：> 与 >>

> 覆盖重定向

将命令输出覆盖到目标文件，原内容被清空

>> 追加重定向

将命令输出追加到文件末尾，原内容保留
$ cat 1.txt > 2.txt # 覆盖 2.txt $ cat 1.txt >> 2.txt # 追加到 2.txt 末尾 $ cat 1.txt 2.txt > 3.txt # 合并两个文件到 3.txt $ echo "" > /var/log/messages # 清空日志文件

管道符 |

将前一个命令的输出作为后一个命令的输入。最常配合 grep 和 more。

$ ls -l /usr/bin | more # 分屏显示 ls 结果 $ ls /usr/bin | grep '^au' # 只看以 au 开头的 $ ps -aux | grep mysql # 查 mysql 进程

查看进程：ps（重点）

格式：ps -aux | grep '关键字' 或 ps -ef | grep '关键字'（macOS 用此写法）

选项说明
-a显示所有用户的进程
-u显示进程的详细状态（CPU/内存/启动时间等）

实时监控：top（知道）

类似 Windows 的任务管理器，实时显示进程信息。快捷键：

  • Shift + M：按内存使用率降序排列
  • Shift + P：按 CPU 使用率降序排列
  • q：退出

关闭进程：kill（重点）

$ kill -9 38997 # 强制关闭进程号 38997
⚠️ 注意：普通用户不能关闭其他用户的进程，只能关闭自己打开的进程。-9 表示强制（SIGKILL）。

查看监听端口：netstat（重点）

格式：netstat [-anptu] | grep '关键字'（root 用户操作）

选项说明
-a查看所有已打开的端口
-n以数字方式显示，不显示别名（http→80, mysql→3306, ssh→22）
-p显示对应的进程的 PID
-t显示 TCP 协议端口
-u显示 UDP 协议端口
# netstat -anptu | grep ssh tcp 0 0 0.0.0.0:22 0.0.0.0:* LISTEN 1111/sshd # ↑ 端口 ↑ 状态 ↑ PID/进程名 # netstat -anptu | grep 3306 # 查 MySQL 端口

查看监听端口：lsof（知道）

# lsof -i # 查看所有已打开进程的端口 # lsof -i:22 # 查 22 端口对应的进程 # lsof -i:3306 # 查 MySQL 端口是否打开
💡 使用场景：启动某个应用程序时，发现端口被占用 → 用 netstat 或 lsof 找到占用进程 → kill -9 PID 关闭它 → 重新启动应用

3用户权限和管理

权限的概念

权限英文缩写数字代号
读readr4
写writew2
执行executex1
无权限—-0

ls -l 输出解析：-rwxr-xr-x 1 admin admin ...

  • 第 1 位：文件类型（-=文件，d=目录，l=链接）
  • 第 2-4 位：拥有者权限（u / user）
  • 第 5-7 位：用户组权限（g / group）
  • 第 8-10 位：其他用户权限（o / other）

修改权限：chmod 字母法

格式：chmod u+rwx 文件名

用户选项

u 拥有者 · g 用户组 · o 其他人 · a 所有人

设置选项

+ 增加权限 · - 撤销权限 · = 设置权限
$ chmod u+w 1.txt # 拥有者增加写权限 $ chmod g-x 1.txt # 用户组撤销执行权限 $ chmod o=rwx 1.txt # 其他人设置为 rwx $ chmod a=r 1.txt # 所有人设置为只读

修改权限：chmod 数字法（重点）

把 r=4, w=2, x=1 相加，分别表示三组权限。

拥有者
rwx
7
4+2+1
用户组
r-x
5
4+0+1
其他人
r-x
5
4+0+1
$ chmod 755 1.txt # rwxr-xr-x（拥有者全权，组和其他只读+执行） $ chmod 644 1.txt # rw-r--r--（默认文件权限） $ chmod 777 1.txt # 所有人全部权限（不安全！）
常见组合： 644=普通文件 · 755=目录/可执行脚本 · 700=只有自己能用 · 600=只有自己可读写

用户管理

# useradd mike # 增加用户 # useradd -g root admin1 # 指定用户组为 root # passwd mike # 修改用户密码（root操作） # userdel -r mike # 删除用户连同其目录 $ who # 查看当前登录用户 $ whoami # 查看当前是谁

$ su - # 切换到 root（需要 root 密码） $ su mike # 切换到 mike（root 切换无需密码） $ passwd # 修改当前用户密码 $ passwd mike # 修改指定用户密码（需 root） $ exit # 退出当前用户（返回上一级或断开SSH）

4其他命令

查找文件：find（重点）

格式：find [路径] -name '文件名' — 路径省略=当前目录，文件名支持通配符（须加引号）

$ find . -name test.sh # 当前目录及子目录 $ find . -name 'abc*.txt' # 通配符必须加引号 $ find / -name '*.sh' # 全盘查找 .sh

软链接：ln（了解）

格式：ln -s 源文件 链接文件 — 源文件必须用绝对路径，不加 -s 是硬链接

软链接

源文件被删 → 链接失效
可链接文件或目录
类似 Windows 快捷方式

硬链接

源文件被删 → 链接仍存在
只能链接普通文件，不能链接目录
大小与源文件一致
$ ln -s /home/admin/mike mike_link # 创建软链接

打包与解包：tar（知道）

打包

把多个文件变成一个
tar -cvf out.tar 文件1 文件2

解包

把一个包提取为多个
tar -xvf out.tar
选项说明
-ccreate — 创建打包文件
-xextract — 解包对应的文件
-vverbose — 显示打包/解包进度
-ffile — 指定打包文件名（必须放最后）
-C大写C — 解包到指定目录

压缩与解压：gzip / bz2 / zip（重点）

格式压缩解压
.tar.gztar -zcvf x.tar.gz 源tar -zxvf x.tar.gz [-C 目录]
.tar.bz2tar -jcvf x.tar.bz2 源tar -jxvf x.tar.bz2 [-C 目录]
.zipzip -r x.zip 源unzip -d 目录 x.zip
记忆口诀：-z 用 gzip，-j 用 bz2（j 像 2 的小变形）。压缩 = create，解压 = extract。

vim 基本操作流程

  3. 编辑修改：正常输入文字

Q1Linux 文件权限有哪几种？怎么用数字法表示？基础+

Linux 有三种权限：

  • r (read) = 4，读权限
  • w (write) = 2，写权限
  • x (execute) = 1，执行权限

权限分三组：u（拥有者）/ g（用户组）/ o（其他人）。数字法把每组的权限位相加：

  • rwx = 4+2+1 = 7
  • r-x = 4+0+1 = 5
  • rw- = 4+2+0 = 6

典型组合：755 = rwxr-xr-x（目录默认）；644 = rw-r--r--（文件默认）。

Q2chmod 字母法和数字法的区别？什么时候用哪个？基础+

字母法适合局部修改，可以增加/撤销单个权限位：

chmod u+w file（只给拥有者加写）
chmod g-x file（只撤销组的执行）

数字法是整体覆盖，一次性写完三组权限：

chmod 755 file（直接写死）

实际工作中数字法用得更多，因为简洁明确。字母法适合微调权限不破坏其他位。

Q3如何查看 Linux 系统中某个端口是否被占用？基础+

两种主流方式：

1) netstat（传统方式，需要 root）：

netstat -anptu | grep 3306

2) lsof（更直观）：

lsof -i:3306

输出里有 LISTEN 状态就表示端口被占用，旁边能看到 PID 和进程名，配合 kill -9 PID 就能释放端口。

Q4tar -zxvf 和 tar -jxvf 的区别？进阶+

区别在压缩算法：

  • -z 用 gzip，处理 .tar.gz。速度快，压缩比中等。最常用。
  • -j 用 bzip2，处理 .tar.bz2。压缩比更高但慢。

除了字母不同，其他选项 xvf 含义一样：x=解压，v=显示过程，f=指定文件。

记忆口诀：z 像 gZip，j 是 Bzip2 里的"j"形状。

Q5vi 编辑器有哪几种模式？如何切换？基础+

三种模式：

  1. 命令模式（默认）：可以用 yy 复制、dd 剪切/删除、p 粘贴、u 撤销
  2. 插入模式：真正能输入文字，按 i 或 a 进入
  3. 末行模式：保存退出，按 shift + : 进入

切换路径：插入模式 ← ESC ← 命令模式 → : → 末行模式。任何模式按 ESC 都能回到命令模式。

Q6测试工作中怎么用 tail -f 排查问题？进阶+

典型流程：

  1. SSH 连到测试服务器
  2. tail -f /var/log/app/error.log 实时跟踪错误日志
  3. 切到浏览器或 Postman 复现 bug
  4. 回到 SSH 窗口看刚滚出来的报错堆栈
  5. 截图错误信息、PID、时间戳 → 附在 bug 单上

比 cat 强在实时——文件追加新内容会自动滚出来；按 Ctrl+C 退出跟踪。

Q7> 和 >> 有什么区别？基础+

> 覆盖：把命令输出覆盖写入目标文件，文件原内容会被清空。

>> 追加：把命令输出追加到文件末尾，原内容保留。

陷阱：用错了会丢日志！比如想给日志加一行，写成 echo "..." > app.log 就把整个日志覆盖掉了。追加永远用 >>。

清空文件的标准用法：echo "" > file 或 > file。

Q8kill -9 和 kill 的区别？什么时候用 -9？进阶+

kill PID 默认发送 SIGTERM (15) 信号，是温柔请求——让进程自己清理资源、关闭连接、保存状态后退出。

kill -9 PID 发送 SIGKILL (9) 信号，是强制终止——内核直接杀掉进程，不给清理机会。

实践建议：

  • 正常情况先用 kill PID
  • 没反应或卡死才用 kill -9
  • 对数据库等有状态服务，强 kill 可能导致数据损坏
Q9软链接和硬链接的区别？陷阱+

软链接（symbolic / ln -s）：

  • 类似 Windows 的"快捷方式"
  • 源文件删除 → 链接失效
  • 可以链接目录，也可以跨文件系统

硬链接（ln 不带 -s）：

  • 指向同一个 inode（同一份数据）
  • 源文件删除 → 链接仍可用（数据还在）
  • 不能链接目录，不能跨文件系统

测试环境部署时常用软链接做"版本切换"：current → release-v1.2/，发版只需改链接指向。

Q10find 怎么查找某类文件？路径可以省略吗？进阶+

格式：find [路径] -name '文件名'

路径可以省略，默认是当前目录及子目录递归查找。

关键陷阱：用通配符时必须加引号！

错误：find . -name *.txt（shell 会先展开 *.txt，可能报错）
正确：find . -name '*.txt'

常用扩展：

  • -type f 只找文件，-type d 只找目录
  • -mtime -7 7 天内修改过
  • -size +10M 大于 10MB
Q11在 vi 里不小心改了文件不想保存怎么办？场景+

救命三连：

  1. 按 ESC（先回到命令模式，无论你在哪个模式）
  2. 输入 :q!（冒号 + q + 感叹号）
  3. 回车 → 强制退出不保存 ✅

反过来，强制保存退出是 :wq!。! 在 vi 末行模式里就是"强制"的意思。

面试时被问"vi 怎么退出"答不出来是经典翻车点，记住 :wq（保存退）和 :q!（不保存退）这两个就够日常用了。

Q12普通用户能 kill -9 root 启动的进程吗？陷阱+

不能。普通用户只能杀自己启动的进程。要杀别人的进程，必须有 root 权限 或用 sudo：

sudo kill -9 PID

这是 Linux 的进程权限隔离机制，避免普通用户误杀系统服务（如 sshd、mysqld）导致服务器瘫痪。

实际工作中如果 SSH 上去发现服务挂了但杀不掉，检查两件事：

  1. 进程是哪个用户启动的？ps -aux | grep xxx 看第一列
  2. 当前是哪个用户？whoami
