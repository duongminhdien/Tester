3测试流程的6个步骤

测试流程的作用：让测试工作有条不紊地开展，确保质量。

①需求评审
→
②计划编写
→
③用例设计
→
④用例执行
→
⑤缺陷管理
→
⑥测试报告

1需求评审

前提：提前阅读需求文档，记录疑问点。
目的：各部门对需求理解一致，查漏补缺，明确功能规则。

2计划编写

核心三问：测什么（目标范围）/ 谁来测（人员安排）/ 怎么测（策略工具）
含准入标准（提测标准）和准出标准（上线标准）。

3用例设计

先设计业务流程用例，后设计单功能模块用例。
用例需经过评审确保覆盖全面。

4用例执行

推荐按优先级执行（P0→P1→P2→P3）。
P0：最高优先级，核心主流程。也可按顺序执行。

5缺陷管理

提交：用例执行失败第一时间提交。
注意：唯一性、可复现、注明版本号。
验证：通过→关闭，不通过→Reopen。

6测试报告

测试阶段最终产出文档，包含：项目概述 / 测试过程回顾 / 统计分析 / 结果确认 / 工作总结与改进。

💡 准入与准出标准：
• 准入（提测标准）：业务主流程（P0）能跑通
• 准出（上线标准）：用例执行率100% / S0级Bug解决率100% / S1级100% / S2S3级≥95%

4业务流程测试 — 流程图法

什么是业务流程测试？

为达到某一个目的，需要将多个功能组合起来使用，这样的操作过程叫业务流程。

意义：确保项目的核心业务能正常使用，覆盖最关键的端到端路径。

流程图法（场景法）

用流程图描述用户的使用场景，通过覆盖流程路径来设计测试用例。

⚠️ 注意：流程图法不需要深入测试功能内部细节，主要测试流程的通路是否正常。每条从开始到结束的路径 = 一条测试用例。

流程图法使用步骤

第一步：找路径

从开始节点到结束节点，有多少条路径就有多少条用例。正向路径（成功）+ 逆向路径（各个节点失败）。

第二步：写用例

流程图中一条路径 = 一条测试用例。包含：用例编号、功能模块、优先级、标题、前置条件、执行步骤、预期结果。

📊用例优先级 & 测试结果标准

优先级定义

  • P0：最核心主流程，必须保证正常
  • P1：次要功能，小功能
  • P2：UI/边界/错误场景
  • P3：错误信息/复杂场景/不常用

测试结果标识

  • Pass 用例通过
  • Fail 用例不通过，发现Bug
  • Block 阻塞，无法继续执行
  • N/A 用例不适用或已作废

提交（New）→ 分派（Assigned）→ 开发修复（Fixed）→ 测试验证（Retest）→ 验证通过关闭（Closed）/ 验证不通过重开（Reopened）

💬面试精讲 — Web功能测试高频题（共12题）

涵盖Web环境、测试流程、业务测试常考面试题，点击展开查看参考答案。

Q1
Web项目环境是由什么组成的？
基础
+

环境定义：项目运行所需要的所有软件和硬件组合。

服务端组成（4要素）：操作系统 + Web应用服务器 + 数据库 + 项目代码

举例：
• LNMP = Linux + Nginx + MySQL + PHP（生产主流）
• WAMP = Windows + Apache + MySQL + PHP（本地开发）

💡 面试亮点：提到Web应用服务器有多种（Nginx/Apache/Tomcat/IIS），数据库有关系型（MySQL/Oracle）和非关系型（Redis/MongoDB），体现技术广度。
Q2
你们公司有几套环境？（超高频面试题）
基础
+

标准答案应包含4种环境：

  • 开发环境（Dev）：开发人员使用，代码频繁迭代
  • 测试环境（Test）：测试人员专用，最核心的测试场所
  • 预生产环境（Pre/UAT）：配置和数据与生产相同，上线前终验
  • 生产环境（Prod）：真实用户使用，禁止随意操作
📌 补充：如果公司只有2套环境（测试+生产），解决进度冲突的方式是区分开发周和测试周，开发期间不测试，测试期间开发不合并新代码。
Q3
测试流程有哪几个步骤？每一步的作用是什么？
基础
+

测试流程共6步：

  1. 需求评审：各部门对需求理解一致，查漏补缺
  2. 计划编写：明确测什么/谁来测/怎么测，含准入准出标准
  3. 用例设计：先业务用例后单功能用例，覆盖所有测试点
  4. 用例执行：按优先级P0→P1→P2→P3执行，记录结果
  5. 缺陷管理：提交→跟踪→验证→关闭，不通过则Reopen
  6. 测试报告：汇总结果，评估质量，决策是否发布
Q4
什么是业务流程测试？为什么要先做业务测试？
基础
+

业务流程：为达到某一目的，需要将多个功能组合使用的操作过程。

业务流程测试：测试核心业务路径是否能跑通（端到端流程验证）。

为什么先做业务测试？
① 确保核心主流程可用（阻塞问题最早发现）
② 单功能缺陷在业务测试中也能发现（提高效率）
③ 符合从整体到局部的测试策略
④ 对应准入标准（P0业务能跑通才开始单功能测试）

Q5
流程图法是什么？如何使用？
基础
+

流程图法（场景法）：用流程图描述用户的使用场景，通过覆盖流程路径设计测试用例。

适用场景：业务场景中涉及多功能的组合逻辑。

使用步骤：
① 根据流程图找路径（从开始到结束，有多少条路径=多少条用例）
② 编写测试用例（一条路径=一条用例，包含正向和逆向）

💡 注意：流程图法主要测流程是否通畅，不深入测试功能细节（那是单功能测试的事）。
Q6
测试用例的优先级如何定义？P0、P1、P2、P3分别代表什么？
基础
+

P0：最高优先级。保证软件最主要、重要的功能，最基本的流程能正常运行（核心主流程）。

P1：次要功能、小功能。

P2：UI、边界、错误场景的设置。

P3：错误信息、较复杂的场景、不常用的场景。

📌 发货业务示例：发货成功（所有项正确）= P0；发货失败（各节点异常）= P1。
Q7
测试计划包含哪些内容？谁来写？有几份？
进阶
+

谁来写：项目测试负责人（测试经理/测试lead）。

有几份：2份——项目总计划 + 个人执行计划。

核心内容：

  • 测什么：测试目标和范围（功能/性能/兼容）
  • 谁来测：人员进度及安排
  • 怎么测：测试策略、测试工具
  • 准入标准：提测标准（主流程P0能跑通）
  • 准出标准：上线标准（用例100%，S0/S1 Bug解决率100%，S2/S3 ≥95%）
Q8
缺陷提交有哪些注意事项？缺陷的生命周期是什么？
基础
+

3个注意事项：
① 唯一性：一个报告只描述一个问题
② 可复现：明确复现步骤、时间、日志截图
③ 注明版本号：发现版本和验证版本都要记录

缺陷生命周期：
New → Assigned（分派）→ Open（确认是Bug）→ Fixed（开发修复）→ Retest（测试验证）→ Closed（通过）/ Reopened（不通过）

⚠️ 特殊状态：Postponed（延后处理）/ Rejected（拒绝，非Bug）
Q9
如何判断一个Bug是前端问题还是后端问题？
进阶
+

需要借助抓包工具（Fiddler/Charles）分析HTTP请求和响应：

前端问题：
① 无请求发出（界面操作没有触发请求）
② 请求参数、请求方法或URL有误
③ 请求正确，响应正确，但界面显示错误

后端问题：
① 请求正常发出，但无响应
② 请求正常，响应内容错误（状态码异常/数据错误）

Q10
测试报告主要包含哪些内容？
基础
+

测试报告的5大核心内容：

  1. 测试项目概述：项目背景、测试范围、测试环境
  2. 测试过程回顾：测试时间、执行情况、主要测试活动
  3. 测试统计分析：用例总数/通过/失败、Bug数/严重度分布、解决率
  4. 测试结果确认：是否满足准出标准，能否发布上线
  5. 工作总结与改进：本次测试经验教训，下次改进方向
Q11
【场景题】发货成功后，用户的订单状态没有变成"待收货"，这个Bug是前端还是后端？如何定位？
高阶
+

分析思路：

  1. 打开抓包工具（Fiddler），过滤TPShop域名
  2. 在后台点击发货，观察是否有"发货"请求发出
  3. 如果有请求：查看响应是否正确（200状态码？响应体中订单状态是否更新？）
  4. 查数据库：订单表的order_status字段是否已更新为"待收货"

定位结论：
• 若DB已更新，前台显示未变 → 前端问题（缓存/渲染逻辑）
• 若DB未更新，发货接口响应错误 → 后端问题
• 若发货接口无响应 → 后端问题（接口挂了）

Q12
【场景题】你需要测试"发货业务"，请完整描述你的测试思路和步骤
高阶
+

完整测试思路（按测试流程6步）：

  1. 需求分析：明确发货业务的规则：后台登录→审核订单→填写物流单号→发货。重点关注物流单号校验规则
  2. 设计测试点：
    • 正向：所有步骤正确 → 发货成功
    • 逆向：登录失败 / 审核不通过 / 物流单号格式错误 / 物流单号与公司不匹配
  3. 编写用例：tp_shipments_001（P0成功）+ 001-004（P1失败场景）
  4. 执行用例：先P0再P1，记录Pass/Fail
  5. 提交缺陷：发现tp_shipments_004 Fail（物流单号错误但发货成功）→ 提交Bug
  6. 验证关闭：开发修复后验证，修复OK则关闭
💡 额外验证点：发货成功后用数据库验证 tp_order 表的状态字段是否更新为"待收货"。

13"用例标题"应该怎么写？
✅ 正确答案：B – 用例标题 = 预期结果（测试点），不是操作步骤。这是面试常考陷阱！错误示例："点击登录按钮"（操作）；正确示例："登录成功（手机号、密码正确）"（测试点）。
