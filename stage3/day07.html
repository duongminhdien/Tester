1APP专项测试概述

APP专项测试是针对移动应用特有特性进行的测试，涵盖兼容性、安装卸载升级、干扰测试（交叉事件）、Push推送以及用户体验等方面。与Web测试不同，APP测试需要考虑更多硬件、网络和操作系统层面的因素。

📱 核心目标
确保APP在不同设备、不同网络环境、不同操作场景下都能稳定运行，提供良好的用户体验。

2兼容性测试

兼容性测试确保APP在不同硬件和软件环境下正常运行。主要从以下几个维度进行：

设备兼容性

  • 手机型号：不同品牌商、不同机型（如华为P30、iPhone 15等）
  • 操作系统版本：安卓（根据在线统计平台数据获取主流版本）、iOS各版本
  • 分辨率：不同屏幕分辨率下的显示效果

屏幕兼容性

  • 尺寸：5.1寸、5.5寸、4.7寸等主流尺寸
  • 类型：刘海屏、水滴屏、曲面屏、折叠屏

网络兼容性

  • 移动数据（4G/5G）
  • WiFi网络
  • 弱网环境

其他兼容性

  • 应用兼容性：与其他APP（如后台播放的音乐应用）的兼容
  • 手机硬件：物理按键（音量键、Home键、电源键）
  • 外部硬件：蓝牙设备、有线设备
  • 系统设置：WLAN、时间、定位等设置对APP的影响
💡 实际操作方法
使用不同的机型打开软件操作，无异常即可。若公司没有太多机型，可参考云测平台或者模拟器进行测试。

3安装、卸载、升级测试

安装测试

正常场景：

  • 从不同渠道安装（应用商店、官网下载、第三方平台）
  • 不同操作系统安装
  • 不同安装路径（手机内存/SD卡）

异常场景：

  • 中断安装（关机、断网），中断之后能否恢复安装
  • 存储空间不足时安装
  • 安装时手动取消或暂停，恢复后是否能正常安装
  • 正在运行时覆盖安装（前台/后台运行：需考虑是否打断用户操作）
  • 低版本覆盖高版本
  • 卸载后再安装（卸载后是否清除数据）

卸载测试

  • 正常卸载（手机卸载/使用第三方软件卸载）
  • 运行时卸载（后台运行中卸载）
  • 取消卸载（第三方软件/二次弹窗确认时取消）
  • 中断卸载（关机）
  • 卸载后数据残留处理
⚠️ 数据残留规则
如果给用户提示确认，用户同意残留可保留数据，拒绝则不可保留。如果不做任何确认提示，默认需要清空残留数据。

升级测试

  • 从临近版本升级（上一次发布的版本）
  • 跨版本升级（如 n-2 升级到 n）
  • 从不同渠道升级
  • 升级成功提醒（红点提示/消息提示）
  • 升级前是否提醒（消息推送提示/强制升级不提醒）
  • 自研升级系统 vs 第三方升级（日常升级/强制升级）
  • 当前版本是否具有升级能力

4干扰测试（交叉事件测试）

干扰测试验证APP在被外部事件打断时是否能正确处理并恢复。常见干扰场景包括：

1通信干扰

接打电话、收发短信、音视频电话

2通知干扰

查看应用推送（其他软件/当前软件的推送）

3设备干扰

连接蓝牙设备、接收文件弹窗提醒

4操作干扰

旋转屏幕、切换网络、打开相机/手电筒/计算器

5电源干扰

低电提醒、插拔充电器（充电动画）

5Push推送测试

服务器端

  • 是否按照规则去推送
  • 推送内容是否正确
  • 推送时间是否准确
  • 推送频率是否合理
  • 推送对象是否正确

手机端

  • 不接收消息：将不会收到任何推送
  • 接收消息：APP在前台/后台/离线时消息的显示方式
  • 消息能否正确打开对应页面
  • 接收但不提醒：手机提醒不会触发
  • 接收且提醒：结合手机模式（静音/震动/铃声）
  • 接收但不显示内容：如"微信发来一条消息"

6用户体验测试

  • UI界面测试：原型图设计是否合理
  • 横竖屏测试：内容展示是否异常
  • 易用性测试：空数据提示、菜单层次是否过深、操作步骤是否过多、按钮位置是否适中
  • 辅助功能：色盲模式、盲人模式
  • 真人体验：找目标用户或公司内部未接触过该项目的人进行体验

7APP性能测试指标

性能指标描述：一定是某种时间内、某种条件下执行某种操作，性能指标如何。性能测试可以考虑和稳定性结合，使用monkey测试时同时使用性能监控工具监控数据。

CPU

  • 基线：如果有基线要求，检查CPU曲线图是否存在长期超过基线的现象；如果没有基线，行业默认90%
  • CPU过高的问题：手机发烫、页面卡顿、电量消耗严重
  • 快速恢复：清空后台运行的进程

内存

  • 内存泄露：内存曲线持续增长（增的远比减的多）
  • 内存溢出：因内存泄露导致，内存持续增加后突然降为0（应用停止运行）
🚨 关键关系
内存溢出一定是因为有内存泄露才会出现。内存泄露不一定导致溢出，但溢出必定由泄露引起。

流量

  • 使用了多长时间，消耗了多少流量
  • 优化方法：数据压缩、不同数据格式、控制访问频次、只获取必要数据、缓存机制、不同网络类型设置不同访问策略

电量

  • 常见高耗电场景：GPS定位、非WiFi网络传输、屏幕亮度、CPU高负载运算、wake_locker锁屏解锁
  • 如果有基线要求则检验是否达标，没有基线可与竞品对比测试

启动速度

  • 冷启动：APP离线状态下启动，时间较长
  • 热启动：APP后台运行状态下启动，时间较短
-- 启动速度测试命令 adb shell am start -W 包名/Activity名

流畅度

  • 帧率（FPS）：每秒切换多少帧
  • 60fps为最佳标准

稳定性（Monkey）

使用monkey工具进行随机事件测试，同时注意性能数据监控和日志收集。

8SoloPi工具与ADB命令

SoloPi工具

SoloPi是一款APP性能测试工具，安装在模拟器或真机上，可以监测CPU、内存、响应耗时、帧率、电池、网络等性能指标。

使用步骤：

  1. 安装SoloPi.apk到模拟器（拖入即可）
  2. 启动SoloPi，确认声明并允许权限
  3. 点击"性能测试"→选择被测APP
  4. 勾选性能测试指标（CPU、内存、响应耗时等）
  5. 启动监测→打开被测APP操作→操作完毕后停止
  6. 查看监测数据图表并导出

ADB环境配置

macOS系统：需要先安装JDK，然后安装SDK，配置环境变量：

# macOS配置环境变量 cd ~ open ~ .zprofile # 添加以下内容 # Android SDK ANDROID_HOME=/Users/用户名/Downloads/android-sdk-macosx PATH=$PATH:$ANDROID_HOME/tools:$ANDROID_HOME/platform-tools:$ANDROID_HOME/build-tools/29.0.3 export ANDROID_HOME # 生效配置 source ~ .zprofile

Windows系统：如果已安装雷电模拟器，只需在系统环境变量Path中添加雷电模拟器安装路径（如 D:\leidian\LDPlayer4）。

常用ADB命令

命令功能说明
adb devices查看当前接入的移动端设备
adb shell进入当前设备命令行
exit退出当前设备命令行
adb shell pm list packages查看设备已安装的软件包
adb shell dumpsys window w | grep mFocusedApp查看当前打开的APP包名和Activity（macOS）
adb shell am start 包名/.Activity名启动指定APP
adb shell am force-stop 包名强制停用APP
adb push 电脑路径 设备路径复制电脑文件到设备
adb pull 设备文件 电脑路径复制设备文件到电脑
adb shell am start -W -n 包名/Activity名启动速度测试

Monkey稳定性测试命令

-- Monkey基本命令格式 adb [-s 设备名] shell monkey \ -p 包名 \ --ignore-crashes \ --ignore-timeouts \ --throttle 400 \ -v \ -s 500 \ 100000 > 指定路径存储文件名
参数说明
-p指定被测应用的包名
--ignore-crashes忽略闪退，闪退后monkey继续发送事件直到完成
--ignore-timeouts忽略超时，超时后monkey继续发送事件直到完成
--throttle 400随机延迟400ms
-v日志详细程度（-v -v -v 最详细）
-s 500指定伪随机数生成器的seed值为500
100000伪随机的事件次数
🔧 常见异常处理
• devices offline（设备离线）→ 重启模拟器
• devices not found（找不到设备）→ 重启模拟器
• more than one devices（多个设备）→ adb disconnect 手机ip 断开不需要的设备

3内存曲线图分析

通过分析内存曲线，可以判断应用是否存在内存泄露和内存溢出问题：

✅ 正常内存曲线

正常 曲线呈锯齿形波动，有升有降，整体平稳

❌ 异常内存曲线（泄露+溢出）

异常 曲线持续上升（泄露），突降为0（溢出，应用崩溃）

4CPU曲线图分析

✅ 正常CPU曲线

正常 曲线始终在基线（90%）以下波动

❌ 异常CPU曲线

异常 曲线长时间超过基线，导致发烫、卡顿、耗电

Q1
APP测试和Web测试有什么区别？
基础
+

参考回答：

APP测试和Web测试主要有以下区别：

1. 兼容性：APP需要考虑不同手机品牌、型号、操作系统版本、屏幕尺寸和类型（刘海屏/折叠屏等），Web主要考虑浏览器兼容性。

2. 专项测试：APP需要额外进行安装卸载升级测试、干扰测试、Push推送测试等，Web不需要。

3. 性能指标：APP需要关注CPU、内存、流量、电量、启动速度、流畅度（FPS），Web主要关注页面加载时间和并发量。

4. 网络测试：APP需要考虑移动数据/WiFi切换、弱网、断网场景。

5. 用户体验：APP需要考虑手势操作、横竖屏、辅助功能等。

Q2
APP兼容性测试需要覆盖哪些方面？
基础
+

参考回答：

APP兼容性测试主要覆盖：

1. 设备型号：不同品牌（华为、小米、OPPO、iPhone等）和机型

2. 操作系统版本：Android不同版本、iOS不同版本

3. 分辨率和屏幕：不同尺寸（5.1/5.5/4.7寸），不同类型（刘海屏/水滴屏/曲面屏/折叠屏）

4. 网络环境：移动数据和WiFi

5. 硬件兼容：手机物理按键、蓝牙设备、有线设备

6. 系统设置：WLAN、时间、定位等对APP的影响

7. 应用兼容：与后台播放类APP的兼容

如果公司没有大量机型，可以使用云测平台或模拟器进行补充测试。

Q3
什么是干扰测试？请举例说明。
基础
+

参考回答：

干扰测试也叫交叉事件测试，指在APP正常使用过程中，被外部事件打断后APP是否能正确处理并恢复。

常见场景：

1. 正在使用APP时来电话或短信

2. 收到其他应用的推送通知

3. 连接或断开蓝牙设备

4. 旋转屏幕（横竖屏切换）

5. WiFi和移动数据自动切换

6. 低电提醒弹窗

7. 插拔充电器（充电动画）

8. 打开手机自带应用（相机、手电筒）

测试重点：被干扰后APP的数据是否丢失、界面是否异常、能否正确恢复到中断前的状态。

Q4
APP升级测试需要关注哪些点？
进阶
+

参考回答：

APP升级测试需要关注：

1. 临近版本升级：从上一个版本升级到当前版本

2. 跨版本升级：从历史版本（如n-2）直接升级到最新版本

7. 降级处理：低版本覆盖高版本的处理逻辑

8. 强制升级 vs 日常升级：不同升级策略的行为是否正确

Q5
什么是内存泄露？什么是内存溢出？它们之间有什么关系？
进阶
+

参考回答：

内存泄露（Memory Leak）：程序申请的内存在使用完后没有被正确释放，导致可用内存越来越少。在曲线图上表现为：内存持续增长，增的远比减的多。

内存溢出（Out Of Memory）：程序请求的内存超出了系统可用内存的大小，导致应用崩溃。在曲线图上表现为：内存持续增加后突然降为0（应用停止运行）。

两者关系：

• 内存溢出一定是因为有内存泄露才会出现

• 内存泄露不一定会导致内存溢出（如果泄露量小，长时间运行才可能触发）

• 修复内存泄露可以预防内存溢出

Q6
APP性能测试包含哪些关键指标？
基础
+

参考回答：

APP性能测试主要包含以下指标：

1. CPU：CPU占用率，行业默认不超过90%的基线

2. 内存：监控是否存在内存泄露和内存溢出

3. 流量：一定时间内消耗的网络流量

4. 电量：一定时间内消耗的电量

5. 启动速度：冷启动和热启动时间

6. 流畅度（FPS）：帧率，60fps为最佳

7. 稳定性：长时间运行是否闪退或崩溃

性能指标描述需要明确：在某种时间内、某种条件下执行某种操作，性能指标如何。

Q7
冷启动和热启动有什么区别？
基础
+

参考回答：

冷启动：APP处于完全离线（未运行）的状态下启动，需要加载所有资源和初始化，所以启动时间较长。

热启动：APP在后台运行的状态下被切换到前台，资源已经在内存中，所以恢复速度极快。

测试方法：使用命令 adb shell am start -W 包名/Activity名，查看输出结果中的 TotalTime 字段来获取启动时间。

区别示例：同一个APP冷启动可能需要500-600ms，而热启动只需要20-30ms。

Q8
什么是Monkey测试？如何使用？
进阶
+

参考回答：

Monkey是Android系统自带的一个测试工具，用于测试APP的健壮性和稳定性。它会向APP发送伪随机的用户事件流（如点击、滑动、旋转等），模拟用户的随机操作。

基本命令格式：

adb shell monkey -p 包名 --ignore-crashes --ignore-timeouts --throttle 400 -v -s 500 100000 > 日志路径

关键参数：

• -p：指定被测APP包名

• --ignore-crashes：忽略闪退继续测试

• --ignore-timeouts：忽略超时继续测试

• --throttle：事件间的延迟时间（ms）

• -v：日志详细程度，最多三个-v

• -s：指定随机种子，相同种子可复现测试

建议：同时使用SoloPi等工具监控性能数据，并收集日志分析问题。

Q10
APP流量优化有哪些方法？
进阶
+

参考回答：

流量优化的常见方法包括：

1. 数据压缩：对传输数据进行压缩（如Gzip）

2. 数据格式优化：选择更高效的数据格式（如JSON替代XML）

3. 控制访问频次：减少不必要的网络请求

4. 只获取必要数据：按需请求，不加载冗余信息

5. 缓存机制：合理使用本地缓存，避免重复请求

6. 网络策略分级：针对不同网络类型（WiFi/4G/5G）设置不同的访问策略，如在移动数据下不自动加载图片

Q11
APP卸载后数据残留应该如何处理？
场景
+

参考回答：

APP卸载后的数据残留处理需要分情况：

1. 有确认提示的情况：如果卸载时给用户弹窗确认，用户同意保留数据则可以保留，用户拒绝保留则必须清空所有残留数据。

2. 无确认提示的情况：如果没有做任何确认提示，默认需要清空所有残留数据，包括缓存文件、配置文件、数据库等。

测试关注点：

• 卸载后重新安装，是否能识别到旧数据

• 残留数据是否会影响新安装的APP

• 用户隐私数据是否被彻底清除

Q12
CPU占用过高时APP会出现哪些问题？如何快速恢复？
基础
+

参考回答：

CPU过高导致的问题：

1. 手机发烫：CPU高负载产生大量热量

2. 页面卡顿：CPU资源不足导致UI渲染变慢

3. 电量消耗严重：高CPU占用直接导致耗电增加

快速恢复方法：清空后台运行的进程，释放CPU资源。

测试标准：如果有基线要求（如CPU不超过90%），检查曲线图是否存在长时间超过基线的情况。如果没有基线，行业默认基线为90%。
