1ADB命令大全

ADB（Android Debug Bridge）是Android SDK中的命令行工具，用于与Android设备进行通信。以下是17个常用ADB命令的完整说明。

设备管理命令

编号命令功能说明
1adb devices查看已连接的设备列表
2adb disconnect 手机ip断开连接的设备
3adb connect 手机ip无线连接设备（手机和电脑需在同一网段）
4adb start-server开启ADB服务
5adb kill-server关闭ADB服务

应用管理命令

编号命令功能说明
6adb install /路径/文件名安装软件包（-r 保留数据 -t 强制覆盖）
7adb uninstall 包名卸载软件包
8adb shell pm list packages获取所有包名（-s 系统应用 -3 第三方应用）
9adb shell dumpsys window | findstr mCurrentFocus获取当前窗口的包名和Activity名（Windows用findstr，Mac/Linux用grep）
10adb shell pm clear 包名清除应用缓存
11aadb shell am start 包名/Activity名启动应用
11badb shell am force-stop 包名强制停止应用
💡 包名 vs Activity名
包名是软件在系统里的唯一标识（如 com.tpshop.malls），Activity名描述APP的某个具体页面（如 .SPMainActivity）。

性能与调试命令

编号命令功能说明
12adb logcat > 本地文件获取手机日志（> 覆盖，>> 追加）
13adb shell am start -W 包名/Activity名获取启动时间（-S 强停后冷启动 -R 数字 指定次数）
14adb shell dumpsys meminfo 包名获取内存信息
15adb shell dumpsys cpuinfo获取CPU占用情况

流量获取命令

-- 第1步：获取应用的userId adb shell dumpsys package 包名 | findstr userId -- 第2步：获取上行流量 adb shell cat proc/uid_stat/userId/tcp_snd -- 第3步：获取下行流量 adb shell cat proc/uid_stat/userId/tcp_rcv
⚠️ 注意事项
cat后的路径是固定格式；userId中的"I"是大写；dumpsys package 后面不加s。

Monkey稳定性测试

-- Monkey常用命令 adb shell monkey -p 包名 10000 -v -v -v --throttle 500 > 本地文件

2日志抓取与分析

测试期间抓取日志是非常重要的，可以避免因为不确定复现步骤而导致Bug无法复现，被开发拒绝。

基本日志抓取

-- 抓取所有日志到文件（覆盖模式） adb logcat > C:\Users\用户名\Desktop\log.txt -- 抓取所有日志到文件（追加模式） adb logcat >> C:\Users\用户名\Desktop\log.txt -- 过滤关键字抓取日志 adb logcat | findstr 关键字 > 路径/文件名.txt

日志分析关键字

拿到日志后，搜索以下关键字来定位问题：

  • exception — 异常信息
  • crash — 崩溃信息
  • ANR — 应用无响应
  • error — 错误信息
🔧 分析工具
可以使用 Notepad++ 打开日志文件进行搜索分析，开发人员通常使用 Android Studio 查看。

3手机抓包（Fiddler）

Fiddler是一个HTTP协议调试代理工具，通过设置代理可以抓取手机端的网络请求。

PC端配置

  1. 配置HTTPS抓取：Tools → Telerik Fiddler Options → HTTPS，勾选 Capture HTTPS CONNECTs，勾选 Decrypt HTTPS traffic 和 Ignore server certificate errors，点击Actions安装证书
  2. 允许远程连接：Tools → Telerik Fiddler Options → Connections，勾选 Allow remote computers to connect，默认端口 8888，配置后重启Fiddler

手机端配置

  1. 确保手机和电脑处于同一网络
  2. 查看电脑IP地址（cmd输入 ipconfig）
  3. 手机浏览器输入 http://电脑IP:8888，下载并安装Fiddler证书
  4. 设置手机密码（安装证书需要）
  5. 修改手机WiFi代理：设置 → 无线网 → 高级 → 代理选择手动 → 输入电脑IP和Fiddler端口号

4手机抓包（Charles）

Charles是另一个常用的抓包工具，操作步骤与Fiddler类似。

Charles端配置

  1. 确保电脑和手机在同一WiFi下
  2. Proxy → Proxy Settings → 设置代理端口 8888
  3. 查看电脑IP（cmd输入 ipconfig）
  4. 设置HTTPS抓包：Proxy → SSL Proxying Settings → Add，添加所有域名和端口
  5. Help → SSL Proxying → Install Charles Root Certificates on a Mobile Device

手机端配置

  1. 连接同一WiFi，设置代理IP和端口（同Fiddler方式）
  2. 手机浏览器访问 chls.pro/ssl，下载安装证书
  3. iOS：设置 → 通用 → 关于手机 → 信任证书
  4. Android：设置 → 安全 → 安装证书

5抓包定位Bug（前端 vs 后端）

通过抓包工具可以精准定位Bug属于前端还是后端。核心思路分两步：

第一步：通过数据库对比

查询数据库中的数据，与前端显示进行对比，确认是哪个环节出了问题。

第二步：通过抓包定位

🖥️ 前端问题

• 抓不到请求（前端未发送请求）

• 请求参数出错（前端拼错了参数）

• 请求正确、响应正确，但前端显示不出来（渲染问题）

⚙️ 后端问题

• 无响应（后端未返回数据）

• 响应出错（后端返回了错误的数据）

🔑 核心判断逻辑
如果请求正确但响应错误 → 后端问题；如果请求本身就有问题或响应正确但显示异常 → 前端问题。

6弱网测试

使用Fiddler可以模拟弱网环境，测试APP在网络不佳时的表现。

设置方法

  1. 修改延迟时间：Rules → Customize Rules → 修改延迟时间（每上传或下载1KB文件需要的时间，单位ms）
  2. 开启延时模拟：Rules → Performance → Simulate Modem Speeds

弱网测试关注点

  • 页面加载是否有友好的Loading提示
  • 请求超时是否有错误提示
  • 回退和刷新是否会造成二次提交
  • 断网后恢复网络，APP能否正常恢复
  • 数据是否丢失或重复

7抓包工具进阶：断点修改数据

抓包工具的原理是在数据传输过程中设置代理服务器。通过断点功能可以拦截并修改请求或响应数据。

Fiddler断点设置

  • Before Requests（请求之前）：拦截并修改请求数据后再发送到服务器
  • After Responses（响应之后）：拦截并修改服务器返回的响应数据后再发送到客户端

设置路径：Automatic Breakpoint → Before Requests / After Responses

💡 断点的测试用途
可以通过修改请求参数测试后端的校验逻辑，通过修改响应数据测试前端的容错处理能力。

8APP发布与开发模型

APP发布流程

  • 测试环境：公共平台标记版本号
  • 线上发布：
    • Android：应用宝、360手机助手、手机品牌应用商店
    • iOS：App Store、iTools
  • 渠道ID：不同渠道发布后需要进行回归测试

敏捷开发模型

  • 迭代周期：2周～4周
  • 工作流程：产品汇总需求产出Backlog → 开迭代计划会 → 迭代开发（需求评审/开发/测试）→ 发布评审（反思会）

瀑布模型 vs 敏捷模型

🏔️ 瀑布模型

测试介入时间：开发编码完成以后。阶段划分清晰，适合需求稳定的项目。

🔄 敏捷模型

测试早期介入，迭代交付。2-4周一个迭代，快速响应需求变化。

4启动时间参数对照

-- 获取启动时间（含冷启动+多次测试） adb shell am start -W -S -R 10 com.tpshop.malls/com.tpshop.malls.SPMainActivity -- 参数说明（均为大写，顺序可调，-R后必须是数字） -W 获取启动时间（TotalTime） -S 启动前强行停止应用（测试冷启动） -R 10 启动次数（连续测试10次）
ThisTime
最后一个Activity的启动时间
TotalTime
所有Activity的启动总时间（重点关注）
WaitTime
系统等待时间（包含前置处理）

Q1
常用的ADB命令有哪些？请写一个Monkey脚本并解释参数含义。
基础
+

常用ADB命令：adb devices、adb install、adb uninstall、adb shell am start 包名/Activity名、adb logcat、adb shell dumpsys meminfo/cpuinfo。

Q2
你用过的HTTP协议调试代理工具有哪些？请说明抓取HTTPS的设置过程。
进阶
+

常用工具有Fiddler和Charles。

Fiddler抓取HTTPS设置：

Q3
如何定位Bug是前端还是后端的？
高频
+

通过两步定位：

第一步：数据库对比 — 查询数据库数据与前端显示对比，确认是哪个环节出了问题。

第二步：抓包分析

• 抓不到请求 → 前端问题（未发送请求）

• 请求参数错误 → 前端问题（参数拼接错误）

• 请求正确但无响应/响应错误 → 后端问题

• 请求正确、响应正确但显示异常 → 前端问题（渲染/解析问题）

Q4
APP测试过程中遇到Crash或ANR，你会怎么处理？
进阶
+

先抓取日志记录：

方式一：adb logcat > 路径/文件名.txt（抓取全部日志）

方式二：adb logcat | findstr crash > 路径/文件名.txt（过滤关键字）

拿到日志后搜索关键字（exception、crash、ANR），查看是哪些方法或异常导致了问题，初步定位原因后交给开发人员深入排查。分析工具可以用Notepad++。

Q5
APP出现Crash的原因有哪些？
进阶
+

1. 内存管理错误：可用内存过低、内存泄露、非授权内存访问

2. 程序逻辑错误：数组越界、堆栈溢出、并发操作冲突、空指针引用

3. 设备兼容问题：不同设备上表现不同

4. 网络因素：网速慢超时、网络切换导致不稳定

Q6
APP出现ANR是什么原因导致的？
进阶
+

ANR（Application Not Responding）的主要原因：

1. 主线程执行了耗时操作（数据库操作、网络请求）

2. 其他进程占用CPU导致本进程得不到时间片

3. 大量数据读写操作

4. 硬件操作（如Camera调用）

5. Thread的join()/sleep()/wait()方法等待超时

6. Service忙导致超时无响应

Q7
GET和POST的区别？
基础
+

1. 参数位置：GET的请求参数放在URL中，POST的参数放在请求体中

2. 参数大小：GET因为参数在URL中，浏览器对URL有长度限制，所以有大小限制；POST没有

3. 用途：一般用GET获取数据，用POST提交数据

4. 安全性：GET参数在URL中可见，相对不安全；POST参数在请求体中

Q8
HTTP和HTTPS的区别？
基础
+

1. 安全性：HTTPS是HTTP的安全加强版，通过加密层保护数据传输

2. 端口：HTTP标准端口80，HTTPS标准端口443

3. 证书：HTTP无需证书，HTTPS需要CA机构颁发的SSL证书

4. 工作层：HTTP工作于应用层，HTTPS工作于传输层

5. 表现形式：HTTPS站点地址栏显示小锁图标

Q9
以前公司的测试流程是什么？
高频
+

1. 需求分析与评审 — 理解需求，参与评审

2. 编写测试计划与方案 — 范围目标、角色职责、资源进度、风险应对、工具环境

3. 设计测试用例与评审 — 使用等价类、边界值、判定表、场景法等方法

Q10
缺陷被提交后，开发人员认为不是问题，怎么处理？
高频
+

1. 首先将问题提交到缺陷管理库备案

Q11
APP性能测试需要重点关注哪些方面？
基础
+

1. CPU和内存占用 — 使用 dumpsys meminfo/cpuinfo 查看

2. 电量和流量消耗 — 关注高耗电场景和流量异常

3. 启动时长 — 冷启动和热启动时间

Q12
软件测试的结束标准是什么？
进阶
+

1. 基于测试用例：功能测试用例通过率100%，非功能性用例95%以上

2. 基于缺陷修复率：严重/主要错误修复率100%，次要/一般错误85%以上

3. 基于缺陷收敛趋势：发现缺陷数量趋近于零

4. 基于覆盖率：测试用例覆盖了全部需求且执行率100%

5. 基于项目计划：与团队达成共识的标准结束点

6. 基于质量/成本/进度：三方面取得平衡

✅知识测验

共15道选择题，测试你对ADB命令、抓包和Bug定位的掌握程度。

1安装一个已存在的APK并保留数据的正确命令是？
A. adb install 文件名
B. adb install -t 文件名
C. adb install -r -t 文件名
D. adb uninstall 文件名
💡 解析：-r 表示保留数据覆盖安装，-t 表示强制覆盖。两者配合使用可以覆盖安装已存在的应用。
2获取手机上第三方应用包名的命令是？
A. adb shell pm list packages -s
B. adb shell pm list packages -3
C. adb shell pm list packages -a
D. adb shell pm list packages -u
💡 解析：-3 获取第三方应用包名，-s 获取系统应用包名，不带参数获取所有包名。
3获取启动时间命令中，-S参数的作用是？
A. 启动前强行停止应用（测试冷启动）
B. 获取启动时间
C. 指定启动次数
D. 指定设备名称
💡 解析：-S 启动前强行停止应用，用于测试冷启动时间。-W 获取时间，-R 指定次数。注意参数均为大写。
4获取APP流量时，第一步需要获取什么？
A. 包名
B. Activity名
C. 设备名
D. userId
💡 解析：获取流量的第一步是通过 adb shell dumpsys package 包名 | findstr userId 获取userId，然后才能查询上行和下行流量。
5Fiddler抓取手机HTTPS包时，手机端需要访问的地址格式是？
A. https://电脑IP:8888
B. http://localhost:8888
C. http://电脑IP:8888
D. ftp://电脑IP:8888
💡 解析：手机浏览器需要访问 http://电脑IP:端口号 来下载Fiddler根证书，默认端口为8888。
6通过抓包发现请求正确但服务器无响应，这属于？
A. 前端问题
B. 后端问题
C. 网络问题
D. 数据库问题
💡 解析：请求正确说明前端没问题，服务器无响应属于后端问题（可能是接口未实现、服务宕机等）。
7adb logcat命令中，> 和 >> 的区别是？
A. > 覆盖文件内容，>> 追加到文件末尾
B. > 追加到文件末尾，>> 覆盖文件内容
C. 两者功能相同
D. > 输出到屏幕，>> 输出到文件
💡 解析：> 覆盖文件内容（如果文件已存在会清空重写），>> 追加在文件末尾（保留原有内容）。
8Charles手机抓包时，手机端下载证书的地址是？
A. http://电脑IP:8888
B. https://charles.io/ssl
C. chls.pro/ssl
D. charles.pro/cert
💡 解析：Charles手机端下载证书需要在浏览器中访问 chls.pro/ssl，然后安装证书。
9Fiddler弱网测试通过哪个菜单开启延时模拟？
A. Tools → Performance
B. File → Simulate
C. Edit → Network Speed
D. Rules → Performance → Simulate Modem Speeds
💡 解析：Fiddler弱网测试需要先在 Rules → Customize Rules 修改延迟时间，然后通过 Rules → Performance → Simulate Modem Speeds 开启。
10敏捷开发模型的迭代周期通常是？
A. 1天～3天
B. 2周～4周
C. 2个月～4个月
D. 半年～1年
💡 解析：敏捷开发的迭代周期通常为2周到4周，快速交付可用的产品增量。
11以下哪个不是APP出现Crash的常见原因？
A. 用户手机屏幕亮度过高
B. 内存泄露导致内存溢出
C. 数组越界
D. 空指针引用
💡 解析：屏幕亮度不会导致APP崩溃。内存溢出、数组越界、空指针引用都是常见的Crash原因。
12获取当前窗口信息在Windows系统使用的过滤命令是？
A. grep
B. find
C. findstr
D. search
💡 解析：Windows使用 findstr 过滤文本，Mac/Linux使用 grep。注意区分操作系统。
13HTTP协议的状态码4XX表示？
A. 成功
B. 客户端错误
C. 服务器错误
D. 重定向
💡 解析：2XX成功，3XX重定向，4XX客户端错误（如404找不到页面），5XX服务器错误。
14以下哪个命令用于清除APP缓存？

15手机抓包的前提条件是？

C. 电脑必须安装Android SDK
D. 手机必须通过USB连接电脑
💡 解析：Fiddler/Charles手机抓包的核心前提是手机和电脑处于同一网络（同一WiFi），不需要Root或USB连接。
