👥三、APP 功能测试 — 拼团购

需求分析（2.5.7 商品拼团活动）

后台功能位置：营销 → 拼团购

后台可以：添加拼团活动、查看拼团活动、启动/编辑/删除活动、查看拼团订单及状态

📋 添加拼团活动规则

  • 一个活动只支持添加一件商品（指明规格）
  • 添加成功后默认是关闭状态，手动开启后才能在手机端展示
  • 拼团标题：长度限制50个字符
  • 必须指明商品规格

📱 手机端拼团列表

  • 显示所有拼团信息
  • 按添加时间先后倒序排列（最新添加的在最上面）
  • 展示：分享图片/拼团商品名称/拼团价格/单独购买价格/成团人数要求

活动详情页展示规则

状态展示内容
未参团展示拼团规则（如：X人成团，原价Y元，拼团价Z元）
已参团但未成团置顶展示"待成团"，显示距离成团还差几人，展示有效时间
拼团成功等待商家确认，有效→进入待发货；无效→拼团失败，金额原路退回

拼团购测试点拆解

📋 列表显示
  • 活动列表倒序排列（最新在最上面）
  • 每条展示5个字段：分享图/名称/拼团价/单购价/成团人数
  • 开启状态才展示给用户
📄 详情页展示
  • 未参团：显示拼团规则
  • 已参团未成团：置顶展示+差人数
  • 已成团：成团数量+1
  • 响应时间不超过2秒
🛒 参团流程
  • 点击一键参团→跳转订单核对页
  • 参团成功（开团）：活动页显示新开团信息
  • 参团成功（成团）：活动页不再展示该团
  • 数据库验证参团记录
✅ 商家确认
  • 商家确认有效→所有参团人员订单变"待发货"
  • 商家确认无效→通知参团成员，金额原路退回
  • 后台多个参团人发货分开发货
  • 参团成员订单分别验证
📱 专项测试
  • 兼容性（安卓10/9/华为P30等）
  • 响应时间不超过2秒
  • 弱网下拼团操作
  • 多用户并发参团（并发场景）

📝四、APP 功能测试 — 注册 / 登录 / 搜索

📌 APP vs Web功能测试核心区别：APP在Web的功能测试基础上，还要额外测试兼容性（不同机型/系统版本）和响应时间（建议≤2秒）。

注册功能测试点（手机APP）

📱 手机号注册
  • 手机号规则：第一位1，第二位≤2，11位自然数
  • 密码：6-16位（字母/数字/符号）
  • 验证码：与图片一致（大小写不限）
  • 推荐人手机：非必填
  • 成功验证：前台+后台+DB三维度
📧 邮箱注册
  • 邮箱格式：xxxx@[126/sina/qq].com
  • xxxx：4-16位，字母/数字/下划线
  • 不能以下划线开头
  • 仅验证邮箱格式
📱 APP专项测试
  • 注册成功后自动跳转首页（登录态）
  • 键盘弹出/收起时界面不变形
  • 手机号/邮箱切换正常
  • 粘贴/复制输入兼容
  • 不同机型输入法兼容

1. APP 测试相比 Web 测试，额外需要哪些专项测试？列举至少5个

APP额外专项测试（8个维度）：

1. 安装/卸载/更新测试：正常安装、存储不足时安装、覆盖安装（旧版→新版）、降级安装、跨版本升级
2. 兼容性测试：不同手机品牌（华为/小米等）、不同Android版本（9/10/11/12）、不同分辨率
3. 中断测试：来电/短信/闹钟打断，APP能否正常恢复
4. 权限测试：相机/位置/存储/通知权限（授权/拒绝的处理）
5. 弱网测试：2G/3G/WiFi信号差时的功能稳定性
6. 性能专项：内存占用/CPU使用率/流量消耗/耗电量
7. 升级测试：版本升级后历史数据是否正常迁移
8. 横竖屏：屏幕旋转时界面自适应，数据不丢失
2. 拼团购的"手机端列表"如何显示顺序？需要设计哪个测试用例来验证？
考察拼团购需求的理解和用例设计
查看答案 ›
需求：手机端拼团列表按添加时间先后倒序排列（最新添加的在最上面）。

验证用例（tp_SpellDeals_001）：
前置：后台按顺序添加5个拼团活动（依次为a→b→c→d→e），并全部开启
步骤：① 打开手机端APP ② 进入拼团活动列表
预期结果：① 活动按时间倒序排列（e在最上，依次为d→c→b→a） ② 每个活动展示：分享图片/拼团商品名称/拼团价格/单独购买价格/成团人数要求

设计思路：通过"添加5个再验证顺序"，能同时验证排序逻辑和字段展示是否完整。
3. 拼团活动详情页在"已参团但未成团"状态下，预期展示什么内容？
考察拼团详情页的状态展示需求
查看答案 ›
已参团但未成团状态，活动详情页展示：

1. 置顶展示"待成团"：将用户已参加的这个团置顶显示
2. 显示距离成团所差人数：如"还差2人成团"
3. 显示该团的有效时间：如"还剩23小时59分钟"（拼团超时会失败）
4. 参团成员位置：显示已参团人的头像，未参团位置显示空位

测试用例（tp_SpellDeals_003）：
前置：已有开启的拼团活动，且用户A已参团但活动未成团
步骤：用户A打开APP → 查看拼团活动详情
预期：① 置顶展示待成团信息 ② 显示还差X人 ③ 显示有效倒计时 ④ 头像显示已参团用户A
4. 商家确认拼团"无效"时，验证哪些内容？
考察拼团失败路径的验证完整性
查看答案 ›
商家确认拼团无效，需要验证（4个维度）：

1. 消息通知：所有参团成员收到通知（如推送消息）："您参与的拼团活动XXX已宣告失败"
2. 金额退款：所有参团成员的支付金额原路退回（退回原支付方式：微信/支付宝/余额）
3. 订单状态：所有参团人的订单状态变为"拼团失败"或"已关闭"
4. 数据库验证：检查参团记录状态字段已更新为失败/退款状态

注意：如果是多人参团（如5人成团），必须验证每个参团成员都收到通知且各自退款。
5. APP注册测试中，"键盘弹出不遮挡输入框"是什么测试类型？如何测试？

查看答案 ›
测试类型：APP专项测试（UI/兼容性/交互）

问题背景：在Android设备上，软键盘弹出后会占据屏幕下半部分，如果页面不做适配，输入框可能被键盘遮挡，用户看不到输入内容。

测试步骤：
1. 打开注册页面
2. 点击最下方的输入框（如"推荐人手机"）
3. 软键盘弹出
4. 验证：当前点击的输入框是否在键盘上方可见
5. 滑动页面：验证键盘弹出时页面是否可以上下滚动

常见Bug：输入框被键盘遮挡（界面不自动上移/不可滚动），属于P2级UI问题。

兼容性：不同品牌手机的输入法键盘高度不同，需要在多款机型上验证。
6. 如何测试APP登录功能的"中断测试"？举例3个场景

中断测试：在操作过程中被外部事件打断，验证APP能否正常恢复。

场景1：登录时来电中断

预期：① 返回APP后登录页面仍在 ② 已填写的账号密码保留（不清空）③ 可以继续点击登录

场景2：登录请求发出中途锁屏
步骤：输入正确账号密码 → 点击登录 → 请求还在处理中时按锁屏键 → 解锁
预期：① 解锁后APP已完成登录 ② 跳转首页显示用户名（不重复显示登录页）

场景3：弱网下登录超时
步骤：设置Fiddler弱网 → 输入正确账号密码 → 点击登录

7. 熟悉APP项目的思路是什么？和Web项目熟悉思路有何不同？
考察对测试思路的整体理解

熟悉思路（完全相同）：
① 用户是谁？② 用户怎么用？
标准：核心业务（用户使用的过程）+ 核心功能（缺失导致无法使用的功能）

信息来源相同：文档（需求文档/用例/用户说明书）+ 人（测试老员工/产品经理/开发）+ 项目软件

核心差异（APP额外关注）：
• APP有安装/卸载这个前置步骤（Web直接打开网页）
• APP有推送通知、系统权限等Web没有的特性
• APP需要关注不同设备的兼容性（Web关注浏览器兼容性）
• APP有中断场景（来电/通知）需要额外测试
• APP的更新机制（应用商店更新/强制更新）需要测试

本质：熟悉项目的思路相同，但测试维度更广。
8. 响应时间测试：为什么APP需要验证"响应时间不超过2秒"？如何测试？
考察性能测试基础
查看答案 ›
为什么要测试响应时间：
响应时间影响用户体验：
• ≤1秒：用户感觉即时响应，体验最佳
• 1~2秒：用户注意到延迟但可接受
• 2~5秒：用户开始不耐烦
• >5秒：多数用户会放弃操作（流失率大幅上升）

行业标准：一般要求API接口响应时间≤2秒，页面加载时间≤3秒。

测试方法：
1. 打开Fiddler（抓包工具）
2. 操作APP页面/功能
3. 在Fiddler中查看请求的Statistics标签 → Timeline，查看请求耗时
4. 也可查看请求从发出到响应完成的时间

记录与建议：如果响应时间无明确需求，测试时记录实际响应时间。若超过5秒，提交"优化建议"类Bug（S3级）。
9. APP支付功能，"支付中断（来电打断）后状态"如何测试？
考察支付功能的中断测试设计
查看答案 ›
支付中断测试场景：

场景1：支付页面调起微信支付时来电
步骤：点击"支付" → 调起微信支付密码输入页 → 此时手机来电 → 接听 → 挂断 → 返回APP
预期结果（关键验证）：
① 订单状态应为"待支付"（未完成支付）
② 不应出现"已扣款但订单无效"（最严重的Bug）
③ 用户可以重新进入支付

场景2：支付中途锁屏
步骤：正在支付过程中 → 按锁屏键 → 解锁 → 返回APP
预期：支付结果与实际扣款一致，无双扣款或订单错误

测试要点：支付状态的一致性（前台显示的状态、实际扣款记录、订单状态、DB记录四者必须一致）

为什么重要：支付是核心业务，任何状态不一致都可能造成用户损失（S0级Bug）。
10. 综合题：用6步测试流程针对"APP拼团购功能"描述完整测试思路

Step 1 需求评审：阅读拼团购需求（2.5.7），确认：活动规则/列表排序/详情展示/成团流程/商家确认逻辑/退款机制。提前记录疑问（如：拼团失败退款多久到账？）

💬面试精讲（共12题）

涵盖APP测试专项、拼团购、注册登录、测试流程在APP中的应用。

Q1
APP测试和Web测试有什么区别？
基础
+

相同点：都需要功能测试（等价类/边界值/场景法）、兼容性测试、性能测试、安全测试。

APP额外的专项测试：

  • 安装/卸载/更新测试（包括覆盖安装/降级安装）
  • 兼容性：不同手机品牌/Android版本/屏幕分辨率
  • 中断测试：来电/短信/闹钟打断后能否正常恢复
  • 权限测试：相机/位置/存储权限的授权与拒绝
  • 性能专项：内存/CPU/流量/耗电量
  • 升级测试：跨版本升级后历史数据迁移
Q2
什么是中断测试？APP为什么需要做中断测试？
基础
+

中断测试：在APP操作过程中，被外部事件打断（来电/短信/闹钟/切换应用等），测试APP能否正常处理中断并在恢复后状态正确。

为什么需要：手机是多任务设备，用户随时可能被打断。如果不做中断测试：

  • 支付中途来电 → 退回APP后订单状态混乱
  • 填写表单中途锁屏 → 解锁后数据丢失
  • 上传图片中途弹通知 → 上传失败且无提示

常见中断测试场景：来电/短信/微信消息/闹钟弹窗/切换到其他APP/锁屏

Q3
APP兼容性测试需要测试哪些维度？如何确定测试机型？
进阶
+

兼容性测试维度：手机品牌（华为/小米/OPPO/vivo/三星）+ Android版本（9/10/11/12）+ 屏幕分辨率（720P/1080P/2K）+ 屏幕尺寸 + 横竖屏 + 深色/浅色模式

如何确定测试机型：

  1. 查看产品的用户数据（用户最多使用哪些机型/系统版本）
  2. 参考应用市场统计（如各Android版本市场占有率）
  3. 公司维护的"兼容设备列表"（必测机型）
  4. 覆盖原则：高中低端机型各选几款，覆盖主流品牌
Q4
拼团购功能，商家确认"无效"的测试用例怎么写？
基础
+

用例：商家确认成团无效（tp_SpellDeals_008）

前置条件：已有拼团活动且活动为开启状态，且拼团已成功（达到成团人数）

步骤：① 打开后台 ② 进入拼团订单 ③ 确认拼团无效

预期结果：① 消息通知参团成员"拼团无效" ② 金额原路退回 ③ 所有参团人员订单状态变为"拼团失败"或"已关闭" ④ DB验证退款记录

验证要点：每个参团成员都要分别验证：收到通知 + 退款到账 + 订单状态正确。

Q5
APP权限测试需要测试哪些内容？拒绝权限后如何处理？
进阶
+

常见APP权限：相机/相册/位置/通知/存储/麦克风/联系人

权限测试场景：

  • 首次请求：使用需要权限的功能时，弹出权限请求弹窗
  • 允许：功能正常使用
  • 拒绝：给出合理提示，引导用户去设置开启权限
  • 永久拒绝：再次使用时直接提示去设置开启（不再弹弹窗）

拒绝权限后正确处理：不能崩溃，应给出提示"请前往设置开启XXX权限"并引导到设置页面。如果APP崩溃或卡死 → S1级Bug。

Q6
熟悉APP项目的标准和思路是什么？
基础
+

核心思路：用户是谁？用户怎么用？

熟悉标准（2个维度）：

  • 核心业务：用户使用的过程（下单/查询/售后/评价等端到端流程）
  • 核心功能：功能缺失会导致用户无法使用（登录/购物车/支付/搜索等）

信息来源：文档（需求文档/用例/说明书）+ 人（测试老员工/产品经理/开发）+ 项目软件（直接体验）

优先级：先熟悉核心业务流程，再深入各核心功能模块。

Q7
APP登录测试除了Web的那些场景，还需要额外测试什么？
进阶
+

Web已有的（账号密码验证/验证码等）基础上，APP额外测试：

  • 记住密码：勾选后下次进入自动填写（不需要再次输入）
  • 自动登录：关闭APP再打开，仍保持登录态（不跳登录页）
  • 第三方登录：微信/QQ/支付宝授权登录流程
  • 登录态保持：后台运行再切换回来，仍是登录状态
  • Token过期：长时间不操作后Token过期，APP给出提示要求重新登录
  • 多设备互踢：同一账号在A手机登录后，在B手机登录，A手机应被踢出
  • 中断测试：登录时来电/锁屏等中断，恢复后状态正确
Q8
什么是APP安装测试？需要测试哪些场景？
基础
+

安装测试场景（7个）：

  1. 正常安装：从应用商城或APK安装，安装成功后功能正常
  2. 存储不足安装：手机存储空间不足时，给出提示（不崩溃）
  3. 覆盖安装（升级）：安装新版本覆盖旧版本，历史数据、账号、设置保留
  4. 降级安装：高版本降回低版本，验证数据兼容性
  5. 卸载后重新安装：历史数据清理，全新安装成功
  6. 安装中断：安装过程中断电/断网，重启后是否能正常处理
  7. 不同来源安装：应用商城/APK直装/企业包等各渠道安装
Q9
【场景题】拼团成功后，商家确认有效，但参团人员A的订单仍显示"待支付"，这是什么Bug？如何定位？
高阶
+

这是Bug。需求：商家确认成团有效后，所有参团人员订单均应变为"待发货"。用户A仍显示"待支付"说明状态更新不完整。

定位步骤：

  1. 确认商家后台操作是否正确（截图后台确认成功的截图）
  2. 用Fiddler查看：商家确认时的接口请求和响应（接口是否成功？返回数据里包含了哪些用户？）
  3. 查数据库：tp_order表中该拼团的所有订单状态字段
  4. 比对：是否只有用户A的订单状态未更新（其他人正常？）

可能原因：① 用户A参团时支付状态异常，被后端逻辑排除 ② 批量更新订单状态时用户A那条更新失败（SQL事务问题）③ 前台缓存未刷新

Bug标题：「【拼团购】商家确认成团有效后，参团成员A订单状态未变更为待发货，仍显示待支付」S1级Bug。

Q10
APP测试中，"响应时间"测试如何进行？有没有标准？
进阶
+

测试方法：使用Fiddler等抓包工具，操作APP，在Fiddler的Statistics→Timeline中查看每个请求的耗时。

行业参考标准：

  • API接口响应：≤1秒（优秀）/ ≤2秒（良好）/ ≤5秒（勉强可用）
  • 页面加载：≤2秒（良好）/ ≤5秒（可接受）

测试注意事项：

  • 如果需求文档有明确要求（如≤2秒）→ 超过则提Bug
  • 如果无明确要求 → 记录实际响应时间，若>5秒提优化建议（S3级）
  • 测试时注意网络环境（WiFi vs 4G，结果会不同）
Q11
APP搜索功能有哪些测试要点（与Web搜索相比有何区别）？
进阶
+

共同测试点（Web也有）：有词搜索（模糊匹配）/ 无词无法搜索 / 无结果提示 / 历史搜索保存 / 历史记录可清除

APP额外测试点：

  • 语音搜索：麦克风权限 → 语音识别 → 识别结果填入搜索框 → 自动搜索
  • 扫码搜索：相机权限 → 扫描条码/二维码 → 自动搜索商品
  • 键盘"搜索"键：手机键盘有专用的搜索键，按下直接触发搜索
  • 历史记录跨会话保持：关闭APP再打开，历史记录仍在
  • 搜索结果滑动：大量结果时，列表滑动流畅不卡顿
  • 网络切换时搜索：WiFi切4G时正在搜索，结果是否正常
Q12
【综合题】如果你是一个APP测试工程师，接手一个全新的电商APP，你的第一步会做什么？
高阶
+

第一步：熟悉项目（不要急着写用例）

  1. 收集资料：需求文档/原型图/已有测试用例/竞品APP
  2. 熟悉核心业务：安装APP，完整走一遍购物流程（搜索→购物车→下单→支付→查订单）
  3. 梳理核心功能：找出所有核心功能（登录/注册/购物车/支付等）
  4. 了解技术栈：Android版本要求/最低支持系统/第三方SDK（微信支付/推送等）
  5. 参加需求评审：在需求评审会上提问，确认所有规则细节
  6. 制定测试计划：测什么/谁来测/怎么测/时间安排/需要哪些测试设备
💡 经验：熟悉项目最有效的方法是"从用户角度完整体验一遍"，比单纯看文档理解更深。遇到疑问立即记录，在需求评审时集中确认。

6熟悉APP项目的核心标准是什么？
✅ 正确答案：B – 熟悉标准：核心业务（用户使用的过程）+ 核心功能（功能缺失导致用户无法使用）。思路：用户是谁+用户怎么用。不是数按钮或背文档，而是理解业务逻辑。
7APP权限测试中，用户"拒绝"相机权限后，APP的正确处理方式是？
✅ 正确答案：B – 拒绝权限后正确处理：给出友好提示，告知用户权限的用途，引导去系统设置开启。APP不能崩溃（S1级Bug），不能强制要求（影响体验），不能忽略（功能会异常）。
8拼团购列表页展示的信息有哪些？（根据需求2.5.7）
✅ 正确答案：B – 需求：列表页显示部分商品信息：分享图片、拼团商品名称、拼团价格、单独购买价格以及成团人数要求。共5个字段，全部需要验证。
9APP注册测试中，以下哪个是"APP专项测试点"（Web没有的）？
✅ 正确答案：C – 软键盘遮挡问题是APP特有的（Web没有虚拟键盘）。A/B/D都是Web测试也需要的功能验证点。APP还有：手机号/邮箱切换Tab、不同输入法兼容、粘贴输入、登录成功后自动跳转等专项点。
10拼团活动添加成功后，后台的默认状态是什么？用户能在手机端看到吗？
✅ 正确答案：B – 需求：添加拼团活动成功后默认是关闭状态，手动开启后才能在手机端展示。测试时需要验证：关闭状态手机端不显示；开启后手机端才能看到。
11APP兼容性测试需要覆盖哪些维度？
✅ 正确答案：B – 兼容性测试是多维度的：手机品牌（华为/小米/OPPO等）、Android版本（9/10/11/12）、分辨率（720P/1080P/2K）、屏幕尺寸、横竖屏切换、深色/浅色模式。只测一个维度会漏测大量兼容性Bug。
12响应时间测试，如果需求无明确规定，超过5秒应该怎么处理？
✅ 正确答案：B – 如果需求无明确规定：记录实际响应时间，>5秒提优化建议（S3/S4级）。如果需求有明确规定（如≤2秒）且超过 → 提Bug（S2级）。不能忽视，也不能过度定级（5秒≠S0严重Bug）。
13APP下单业务的核心流程是？
✅ 正确答案：B – APP下单核心业务流程：登录→搜索商品→加购物车→去结算→确认订单（选地址/优惠券等）→选支付方式→完成支付。与Web购物流程相同，但APP还需要额外测试支付中断等场景。
14APP登录的"多设备互踢"测试场景是什么？
✅ 正确答案：B – 多设备互踢：同一账号在设备A登录 → 再在设备B登录 → 设备A收到"您的账号在其他设备登录"提示，被强制退出。这是常见的账号安全机制，防止账号共享。
15【综合题】测试APP拼团购功能，"支持一键参团（tp_SpellDeals_004）"用例的预期结果是什么？
✅ 正确答案：B – 需求：点击一键参团后，跳转到订单核对页（用户确认地址/支付方式/金额）。不是直接完成，而是跳转到订单核对页让用户确认后再支付参团。与课堂用例一致：预期现象=跳转到订单核对页。
