1框架与 unittest 介绍

框架（Framework）是为了解决一类问题的功能集合，提供了通用的解决方案。

unittest 是 Python 自带的单元测试框架，测试人员用它作为自动化测试的执行框架，用来管理和执行测试用例。

✅ 自带无需安装

Python 标准库的一部分，import unittest 即可使用，无需 pip 安装

🔧 组织多个用例

能将多个测试用例文件组装在一起统一执行

🎯 丰富的断言

提供 assertEqual、assertTrue 等断言方法，自动判断结果

📊 生成测试报告

配合第三方库生成 HTML 格式的可读测试报告

3TestCase 测试用例

TestCase 是书写真正用例代码的地方，一个 TestCase 对应一个测试类，类中每个方法是一个测试用例。

使用步骤（4 步）

  1. 导包：import unittest
  2. 定义测试类：继承 unittest.TestCase，类名习惯以 Test 开头
  3. 书写测试方法：方法名必须以 test 开头，方法体就是真正的用例代码
  4. 执行：右键运行 / 主程序 unittest.main()
import unittest class TestDemo(unittest.TestCase): def test_method1(self): # 必须 test 开头 print('测试方法一') def test_method2(self): print('测试方法二') if __name__ == '__main__': unittest.main()

注意事项

⚠️ 常见错误
• 代码文件名满足标识符规则（字母/数字/下划线，不能数字开头）
• 代码文件名不要使用中文（会导致 IDE 无法识别为测试文件）
• 测试方法名必须以 test 开头，否则不会被执行
• 测试类必须继承 unittest.TestCase

执行方式

  • 在类名后右键运行：执行类中的所有测试方法
  • 在方法名后右键运行：只执行当前方法
  • 主程序使用 unittest.main()：执行该文件中所有测试方法

4TestSuite 和 TestRunner

TestSuite（测试套件）：将多个用例文件组装在一起。
TestRunner（测试执行）：执行 TestSuite，输出结果。

完整步骤

  1. 导包 import unittest
  2. 实例化套件对象 suite = unittest.TestSuite()
  3. 添加用例方法
  4. 实例化执行对象 runner = unittest.TextTestRunner()
  5. 执行 runner.run(suite)

添加用例的两种方式

import unittest from case1 import TestDemo1 from case2 import TestDemo2 suite = unittest.TestSuite() # 方式一：逐个添加（精确控制顺序） suite.addTest(TestDemo1('test_method1')) suite.addTest(TestDemo1('test_method2')) suite.addTest(TestDemo2('test_method1')) # 方式二：addTest + makeSuite 添加整个类（推荐） suite.addTest(unittest.makeSuite(TestDemo1)) suite.addTest(unittest.makeSuite(TestDemo2)) runner = unittest.TextTestRunner() runner.run(suite)
📋 执行结果的符号含义
• . — 用例通过（pass）
• F — 用例不通过（Fail，断言失败）
• E — 用例代码错误（Error，代码本身有 bug）

5TestLoader 测试加载

TestLoader 是 TestSuite 的增强版，适合有大量用例文件时批量加载。

使用步骤

  1. 导包 import unittest
  2. 实例化加载对象并加载用例 → 得到套件对象
  3. 实例化执行对象并执行
import unittest # 加载当前目录下所有以 test_ 开头的 .py 文件 suite = unittest.TestLoader().discover('.', 'test_*.py') # 执行 unittest.TextTestRunner().run(suite)
💡 discover() 两个参数
• 第一个参数：用例所在的目录（'.' 表示当前目录）
• 第二个参数：文件名匹配规则（支持通配符，如 'test_*.py'）
将来的项目结构：用例统一放在 case/ 目录，命名为 test_项目_模块_功能.py

6Fixture 测试夹具

Fixture 是一种代码结构，让某些代码在用例执行前后自动运行，用于环境准备和资源清理。

📌 以登录测试为例，执行顺序：
① 打开浏览器（一次）→ ② 打开网页点击登录 → ③ 输入数据1点击登录 → ④ 关闭页面 →
② 打开网页 → ③ 输入数据2 → ④ 关闭页面 → ⑤ 关闭浏览器（一次）

方法级别 Fixture（最常用）

在每个测试方法执行前后自动调用：

class TestLogin(unittest.TestCase): def setUp(self): # 方法前置：每个用例执行前自动调用 print('2. 打开网页，点击登录') def tearDown(self): # 方法后置：每个用例执行后自动调用 print('4. 关闭页面') def test_1(self): print('3. 输入用户名密码1，点击登录') def test_2(self): print('3. 输入用户名密码2，点击登录')

类级别 Fixture

在整个测试类的所有方法执行前后只调用一次，必须写成类方法：

@classmethod def setUpClass(cls): # 类前置：整个类执行前只调用一次 print('1. 打开浏览器') @classmethod def tearDownClass(cls): # 类后置：整个类执行后只调用一次 print('5. 关闭浏览器')

模块级别 Fixture（了解）

在整个代码文件执行前后各调用一次，定义在类外部：

def setUpModule(): # 模块前置（在类外部定义） pass def tearDownModule(): # 模块后置 pass

三级 Fixture 执行顺序

✅ 完整执行顺序：
setUpModule → setUpClass → setUp → test_1 → tearDown → setUp → test_2 → tearDown → tearDownClass → tearDownModule

7断言（Assert）

断言让程序自动判断预期结果和实际结果是否相符，无需人工比对。断言失败时，测试方法标记为 F。

常用断言方法

断言方法说明等价于
assertEqual(a, b)断言 a == b最常用，验证返回值
assertNotEqual(a, b)断言 a != b验证不相等
assertTrue(x)断言 x 为 Truebool(x) is True
assertFalse(x)断言 x 为 Falsebool(x) is False
assertIn(a, b)断言 a in b验证包含关系
assertNotIn(a, b)断言 a not in b验证不包含

使用示例

import unittest def add(a, b): return a + b class TestAdd(unittest.TestCase): def test_1_1_2(self): """1 + 1 = 2""" result = add(1, 1) self.assertEqual(2, result) # 期望, 实际 def test_1_2_3(self): """1 + 2 = 3""" self.assertEqual(3, add(1, 2))
💡 assertEqual 参数顺序约定
assertEqual(期望值, 实际值) — 第一个参数是期望结果，第二个是实际调用结果。顺序不影响断言是否通过，但影响失败时的错误信息可读性。

8登录功能测试完整案例

使用 unittest 框架对 login() 函数进行完整的测试：

import unittest # 被测函数（开发提供，不要修改） def login(username, password): if username == 'admin' and password == '123456': return '登录成功' else: return '登录失败' class TestLogin(unittest.TestCase): def test_correct(self): """正确的用户名和密码""" self.assertEqual('登录成功', login('admin', '123456')) def test_wrong_user(self): """错误的用户名""" self.assertEqual('登录失败', login('root', '123456')) def test_wrong_pwd(self): """错误的密码""" self.assertEqual('登录失败', login('admin', '123123')) def test_wrong_both(self): """错误的用户名和密码""" self.assertEqual('登录失败', login('aaa', '123123')) if __name__ == '__main__': unittest.main()

基础
+

方法类型普通实例方法类方法，必须加 @classmethod
参数selfcls
典型用途打开网页、准备数据打开浏览器、建立数据库连接

常见错误：给 setUpClass 忘记加 @classmethod 装饰器，会导致运行出错。

Q7
unittest 中的断言是什么？为什么要用断言？
基础
+

断言让程序自动判断预期结果和实际结果是否相符，无需人工对比。

为什么用断言（不用 if 判断）：

  • 断言失败时，框架会自动标记该用例为 F（Fail）
  • 失败时提供详细的错误信息（期望值 vs 实际值）
  • 用 if 判断只是打印，框架无法识别是否"通过"
  • 统计通过率需要框架知道每个用例是否 Pass/Fail

最常用：assertEqual(期望值, 实际值)

Q8
执行结果的 . F E 各代表什么？
基础
+
  • . Pass — 用例执行通过，断言结果符合预期
  • F Fail — 用例断言失败，实际结果与预期不符。这说明测试发现了 bug！
  • E Error — 用例代码本身有错误，如语法错误、变量未定义。用例代码有问题，不是被测功能的 bug。

区分 F 和 E 很重要：F 是被测功能的问题（需要开发修复），E 是测试脚本的问题（需要测试人员修复）。

Q9
下面代码哪里有问题？
陷阱
+
import unittest class TestDemo(unittest.TestCase): def check_login(self): # 问题在这 self.assertEqual('登录成功', ...) @classmethod def setUp(self): # 问题在这 pass

两个问题：

  1. check_login 方法名不以 test 开头，不会被 unittest 执行。应改为 test_check_login。
  2. setUp 加了 @classmethod 装饰器，这是错误的。方法级 Fixture 是普通实例方法（用 self），类级 Fixture 才用 @classmethod（setUpClass/tearDownClass）。setUp + @classmethod 会报错。
Q10
有 3 个测试方法，setUp 和 tearDown 各执行几次？
陷阱
+

答案：setUp 执行 3 次，tearDown 执行 3 次。

setUp 和 tearDown 在每个测试方法前后各执行一次，3 个方法就各执行 3 次。

而 setUpClass 和 tearDownClass 各只执行 1 次（整个类开始/结束时）。

完整执行顺序：

  1. setUpClass
  2. setUp → test_1 → tearDown
  3. setUp → test_2 → tearDown
  4. setUp → test_3 → tearDown
  5. tearDownClass
Q11
测试方法的执行顺序是什么？
进阶
+

unittest 中，测试方法按方法名的 ASCII 顺序（字母顺序）执行，而不是按定义顺序。

例如：test_a、test_b、test_c 会按 a→b→c 执行。

命名建议：

  • 给方法加编号前缀：test_01_login、test_02_logout
  • 用语义命名：test_correct_pwd、test_wrong_user（可读性好）

如果测试用例之间有严格顺序依赖，建议用 TestSuite 手动控制顺序。

Q12
在实际项目中如何组织 unittest 测试？
场景
+

推荐目录结构：

project/ ├── case/ # 所有测试用例 │ ├── test_login.py # 命名：test_项目_模块_功能.py │ ├── test_register.py │ └── test_search.py ├── data/ # 测试数据 JSON 文件 │ └── login_data.json ├── report/ # 测试报告 │ └── result.html └── run.py # 主运行文件

run.py 内容：

import unittest suite = unittest.TestLoader().discover('case/', 'test_*.py') unittest.TextTestRunner().run(suite)

进阶：配合 HTMLTestRunner 生成报告，把 TextTestRunner 替换成 HTMLTestRunner 并指定输出文件路径。
