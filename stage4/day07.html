1继承的概念

继承描述的是类与类之间的关系（is-a 关系），是面向对象三大特性之一。

🎯 继承的好处
• 减少代码冗余，相同的代码不需要写多次
• 提高编程效率，子类自动拥有父类的属性和方法
• 便于维护，修改父类，所有子类同步更新

继承的语法

# 写法 1：显式继承 object（最完整） class 类A(object): pass # 写法 2：空括号 class 类A(): pass # 写法 3：不写括号（推荐，等同于继承 object） class 类A: pass # 类 B 继承 类 A class 类B(类A): pass
📝 术语
• 类 A：被继承的类，称为父类（或基类、super class）
• 类 B：继承别人的类，称为子类（或派生类、sub class）
• object：Python 中最原始的类，所有类都默认继承它

完整示例：动物继承体系

class Animal: """动物类""" def __init__(self, name, age): self.name = name self.age = age def eat(self): print(f'{self.name} 吃东西') def sleep(self): print(f'{self.name} 睡觉') class Cat(Animal): # 猫继承动物 def catch(self): print(f'{self.name} 会抓老鼠') class Dog(Animal): # 狗继承动物 def look_the_door(self): print(f'{self.name} 正在看家') class XTQ(Dog): # 哮天犬继承狗 def fly(self): print(f'{self.name} 在天上飞') xtq = XTQ('哮天犬', 100) xtq.eat() # 来自爷爷类 Animal xtq.look_the_door() # 来自父类 Dog xtq.fly() # 来自自己 XTQ
✨ 继承的传递性
C 继承 B，B 继承 A，则 C 可以使用 A 类中的属性和方法。
XTQ → Dog → Animal → object，xtq 对象能用整条链路的所有公有方法。

对象调用方法的查找顺序

当执行 对象.方法名() 时，Python 会按以下顺序查找：

  1. 先在自己的类中查找，找到 → 使用
  2. 没找到，去父类中查找，找到 → 使用
  3. 没找到，去父类的父类中查找，找到 → 使用
  4. ... 一直找到 object 类
  5. 都没找到 → 报错 AttributeError

2方法重写（override）

重写就是在子类中定义一个和父类方法同名的方法，当子类对象调用该方法时，会执行子类自己的版本。

为什么要重写？

当父类中的方法实现不能满足子类对象的需求时，可以通过重写来定制子类自己的行为。

两种重写方式

1覆盖式重写

父类中的功能全部不要，直接在子类中重新写一遍方法

2扩展式重写

父类中的功能还需要，但要在基础上添加新功能，用 super() 调用父类方法

覆盖式重写示例

class Dog: def bark(self): print('汪汪汪叫......') class XTQ(Dog): # 父类的 bark 不能满足需求，完全覆盖重写 def bark(self): print('嗷嗷嗷叫.....') xtq = XTQ() xtq.bark() # 嗷嗷嗷叫.....（父类的汪汪汪没了）

扩展式重写示例（使用 super()）

class Dog: def bark(self): print('汪汪汪叫......') print('汪汪汪叫......') class XTQ(Dog): def bark(self): # 1. 先调用父类的方法（保留原有功能） super().bark() # 2. 再添加新功能 print('嗷嗷嗷叫.....') print('嗷嗷嗷叫.....') xtq = XTQ() xtq.bark() # 汪汪汪叫...... # 汪汪汪叫...... # 嗷嗷嗷叫..... # 嗷嗷嗷叫.....
💡 super() 的用法
super().方法名() 表示调用父类的同名方法。在子类的重写方法中使用，可以保留父类的原有功能再添加新逻辑。

3多态（polymorphism）

📘 定义
多态：不同的子类对象调用相同的方法，产生不同的执行结果。
多态是一种调用代码的技巧，依赖于继承和方法重写。

多态示例

class Dog: def game(self): print('普通狗简单的玩耍...') class XTQ(Dog): def game(self): # 重写 game 方法 print('哮天犬在天上玩耍...') class Person: def play_with_dog(self, dog): """dog 可以是 Dog 类或其子类的对象""" print('人和狗在玩耍...', end='') dog.game() # 关键：同一行代码，不同对象产生不同结果 xw = Person() xw.play_with_dog(Dog()) # 人和狗在玩耍...普通狗简单的玩耍... xw.play_with_dog(XTQ()) # 人和狗在玩耍...哮天犬在天上玩耍...
🎯 多态的价值
play_with_dog 方法不需要修改，就能适配 Dog 和 XTQ 两种不同的狗。新增一种狗（如博美 Pomeranian）也不需要改这个方法。

4公有与私有权限

Python 定义类时，可以给属性和方法设置访问权限，规定它们能在什么地方使用。

🌍 公有（public）

  • 直接定义的属性/方法默认就是公有
  • 可在任何地方访问（类内、类外、子类）
  • 只要有对象就能用

🔒 私有（private）

  • 只能在类的内部定义（class 缩进中）
  • 属性/方法名前加两个下划线 __
  • 只能在当前类内部使用，不能在类外和子类直接使用

应用场景

  • 一般情况下，定义的属性和方法都为公有
  • 某个属性不想被外部直接修改 → 定义为私有
  • 某个方法是内部辅助方法，不希望外部调用 → 定义为私有

完整案例：保护年龄属性

class Person: def __init__(self, name, age): self.name = name # 公有 self.__age = age # 私有（前加双下划线） def __str__(self): # 公有方法 return f"{self.name}, {self.__age}" def set_age(self, age): # 公有方法，修改私有属性 if age < 0 or age > 120: print('提供的年龄信息不对') return self.__age = age xw = Person('小王', 18) print(xw) # 小王, 18 xw.__age = 10000 # 这是给对象添加一个新的 __age 属性，不是修改私有属性！ print(xw) # 小王, 18（__str__ 中的 __age 仍是 18） xw.set_age(10000) # 提供的年龄信息不对 xw.set_age(25) # 修改成功 print(xw) # 小王, 25
⚠️ 注意：私有属性的"伪私有"机制
Python 没有真正的私有，__age 实际被改名成 _Person__age（名称改写）。在类外仍可通过 xw._Person__age 强行访问，但极度不推荐。

5类对象 vs 实例对象

Python 中"一切皆对象"，类本身也是对象。

🏛️ 类对象

类对象就是类本身，使用 class 定义的类。代码执行时由解释器自动创建。

作用：

  • 使用类对象创建实例对象
  • 存储类的特征值（类属性）

🎁 实例对象

由类对象（类）创建出来的对象，即 类名() 实例化的结果，简称实例。

没有特殊说明时，"对象"通常都指实例对象。可以保存自己的特征值（实例属性）。

6实例属性 vs 类属性

实例属性（Instance Attribute）

  • 概念：每个实例对象具有的特征，每个实例都有自己独立的一份
  • 定义：一般在 __init__ 方法中通过 self.属性名 = 值 定义
  • 内存：每个实例都保存一份，内存中有多份
  • 访问：实例.属性名 或 类内 self.属性名

类属性（Class Attribute）

  • 概念：是类对象的特征，是整个类共享的
  • 定义：在类内部、方法外部直接定义的变量
  • 内存：只有类对象保存一份，所有实例共享
  • 访问：类名.属性名（推荐）或 实例.属性名（不推荐）
⚠️ 什么时候定义类属性？
大部分属性都用实例属性（self 定义）。当某个属性描述的是整个类的特征（修改它会影响所有实例的这个特征），才定义为类属性。
例如：游戏的"历史最高分"、统计"创建了多少个对象"。

属性查找顺序

使用 实例.属性 访问时：

  1. 先在实例属性中查找，找到 → 使用
  2. 没找到，去类属性中查找，找到 → 使用
  3. 都没找到 → 报错

案例：统计工具数量

class Tool: count = 0 # 类属性，记录创建对象的个数 def __init__(self, name): self.name = name # 实例属性 Tool.count += 1 # 通过类名修改类属性 print(Tool.count) # 0 tool1 = Tool('锤子') print(Tool.count) # 1 tool2 = Tool('扳手') print(Tool.count) # 2 print(tool2.count) # 2（实例找不到 count，去类属性找到了）
❌ 不要用 实例.类属性 = 值 修改类属性
tool1.count = 99 不会修改类属性，而是给 tool1 添加了一个同名的实例属性。修改类属性请用 类名.属性 = 值。

7三种方法类型

方法类型装饰器首参数使用场景
实例方法无self需要使用实例属性
类方法@classmethodcls不需要实例属性，需要类属性
静态方法@staticmethod无既不需要实例属性也不需要类属性

实例方法（Instance Method）

class 类名: def 方法名(self): # 直接定义就是实例方法 pass # 调用方式 实例对象.方法名()

类方法（Class Method）

class 类名: @classmethod # 必须加装饰器 def 方法名(cls): # 第一个参数是 cls，表示类对象 pass # 调用方式 类名.方法名() # 推荐 实例对象.方法名() # 也可以

静态方法（Static Method）

class 类名: @staticmethod # 必须加装饰器 def 方法名(): # 没有 self 或 cls 参数 pass # 调用方式 类名.方法名() 实例对象.方法名()
💡 cls 和 self 的关系
• self 是实例对象，由谁调用方法就是谁
• cls 是类对象（类名），由 Python 自动传递
• 都不需要手动传递，约定俗成的命名

8Game 综合案例

需求：设计一个游戏类，包含历史最高分（类属性）和玩家姓名（实例属性），具有三种不同类型的方法。

import random class Game: top_score = 0 # 类属性：历史最高分 def __init__(self, name): self.player_name = name # 实例属性：当前玩家 @staticmethod def show_help(): # 静态方法：不需要 self/cls print('这是游戏的帮助信息') @classmethod def show_top_score(cls): # 类方法：需要访问类属性 print(f'历史最高分: {cls.top_score}') def start_game(self): # 实例方法：需要访问实例属性 score = random.randint(10, 100) print(f'玩家 {self.player_name} 得分: {score}') if score > Game.top_score: Game.top_score = score if __name__ == '__main__': Game.show_help() Game.show_top_score() player = Game('小王') player.start_game() Game.show_top_score()

9文件操作

文件：可以存储在长期存储设备（硬盘、U 盘）上的一段数据。

📁 文件的分类
根据能否用记事本打开：
• 文本文件：可以用记事本打开，如 .txt、.py、.md、.json
• 二进制文件：不能用记事本打开，如 .mp3、.mp4、.png、.jpg、.exe

文件操作三步流程

  1. 打开文件 open()
  2. 读写文件 read() / write()
  3. 关闭文件 close()

open() 函数

open(file, mode='r', encoding=None)
参数含义说明
file文件路径相对路径（./、../）或绝对路径（C:/、D:/）
mode打开模式r / w / a
encoding编码格式utf-8（常用，1 汉字 = 3 字节）、gbk（1 汉字 = 2 字节）

三种打开模式

r

只读（read）
默认模式。如果文件不存在会报错。

w

只写（write）
如果文件存在，会覆盖原文件内容！文件不存在则创建。

a

追加（append）
在文件末尾写入新内容，不覆盖原内容。文件不存在则创建。

读文件 read()

# 1. 打开文件 f = open('a.txt', encoding='utf-8') # 2. 读取文件，返回字符串 data = f.read() print(data) # 3. 关闭文件 f.close()

写文件 write()

# 1. 以写模式打开 f = open('a.txt', 'w', encoding='utf-8') # 2. 写入内容（必须是字符串） f.write('好好学习\n天天向上') # 3. 关闭文件（自动保存，同步内存到硬盘） f.close()

推荐写法：with 语句（自动关闭）

with open('a.txt', 'r', encoding='utf-8') as f: data = f.read() print(data) # 出了 with 缩进，文件自动关闭，不用手动 close()
✅ 为什么推荐 with 写法
• 自动关闭文件，即使发生异常也能保证关闭
• 代码更简洁，不会忘记 close
• 这是 Python 处理文件的最佳实践

读写文件应用：保存测试数据

在自动化测试中，文件操作常用于：

  • 从文件读取测试数据，进行数据驱动测试
  • 把测试结果写入日志文件，便于查看分析
  • 持久化保存配置信息、最高分等需要长期保留的数据

当执行 xtq.eat() 时，Python 按继承链向上查找：

1
先在 XTQ 中查找 eat()
❌ 没找到
2
去父类 Dog 中查找 eat()
❌ 没找到
3
去 Animal 中查找 eat()
✅ 找到，使用
💡 MRO 全称 Method Resolution Order（方法解析顺序）。可以通过 类名.__mro__ 查看：
XTQ.__mro__ → (XTQ, Dog, Animal, object)

3覆盖式 vs 扩展式重写对比

🔄 覆盖式重写

class XTQ(Dog): def bark(self): print('嗷嗷叫') # 父类的汪汪叫不要

输出：嗷嗷叫

➕ 扩展式重写

class XTQ(Dog): def bark(self): super().bark() print('嗷嗷叫')

输出：汪汪叫 + 嗷嗷叫

4多态：一行代码多种行为

🎭 同一个 game() 方法，不同对象不同结果
xw.play_with_dog(Dog()) # → 人和狗在玩耍...普通狗简单的玩耍... xw.play_with_dog(XTQ()) # → 人和狗在玩耍...哮天犬在天上玩耍... xw.play_with_dog(Pomeranian()) # 新增博美 # → 人和狗在玩耍...博美撒娇地玩耍... # 不需要修改 play_with_dog 方法！
🎯 多态 = 继承 + 重写 + 父类引用指向子类对象
play_with_dog 期待"狗类或其子类对象"，传不同子类进去，dog.game() 就调用不同子类的实现。这是开闭原则的体现：对扩展开放，对修改关闭。

Q1
什么是继承？写出 Python 继承的语法。
基础
+

继承描述类与类之间的 is-a 关系。子类继承父类后，自动拥有父类的所有公有属性和方法，无需重复编写。

语法：

class 子类(父类): pass

好处：

  • 减少代码冗余，提高复用性
  • 子类只需关注自己独特的部分
  • 修改父类，所有子类同步更新

注意：不写括号也是继承（默认继承 object），即 class A: 等价于 class A(object):。

Q2
什么是方法重写？为什么要重写？重写后如何调用父类方法？
基础
+

什么是重写：在子类中定义一个与父类同名的方法，覆盖父类的实现。

为什么重写：父类的方法实现不能满足子类对象的需求，需要子类提供自己的实现。

两种方式：

  • 覆盖式重写：父类功能全部不要，子类完全重新写。
  • 扩展式重写：父类功能还要保留，再加新功能，用 super().方法名() 调用父类方法。

调用父类方法：

class XTQ(Dog): def bark(self): super().bark() # 调用父类的 bark print('嗷嗷叫')
Q3
什么是多态？多态有什么作用？
基础
+

多态：不同的子类对象调用相同的方法，产生不同的执行结果。多态是一种调用代码的技巧，依赖于继承和方法重写。

三要素：

  1. 继承（子类继承父类）
  2. 重写（子类重写父类方法）
  3. 父类引用指向子类对象（传参时传不同子类对象）

作用：

  • 调用方代码不变，能适配多种子类对象
  • 新增子类时不需要修改原有代码（开闭原则）
  • 提高代码的可扩展性和可维护性

测试场景：基础测试类提供 setUp/tearDown，各种子类测试用例自动使用基类钩子，无需重复编写。

Q4
公有属性和私有属性的区别？如何定义私有属性？
基础
+

区别：

对比项公有私有
命名普通名字双下划线开头 __age
类内✅ 可访问✅ 可访问
类外✅ 可访问❌ 不可直接访问
子类✅ 可继承使用❌ 不可直接使用

定义方式：在属性名或方法名前加双下划线，且只能在类内部定义。

应用场景：需要保护的数据（如年龄、密码），通过公有的 setter 方法验证后才能修改。

注意：Python 没有真正的私有，__age 实际改名成 _Person__age，类外仍可强行访问，但极不推荐。

实例属性和类属性的区别？分别什么时候用？
进阶
+
对比项实例属性类属性
定义位置__init__ 中 self.x = ...类内方法外
归属实例对象类对象
内存每个实例独立一份整个类共享一份

什么时候用类属性：当某个属性描述的是整个类的特征，所有实例共享，例如：

  • 统计创建了多少个对象（count）
  • 游戏的历史最高分（top_score）

大部分属性用实例属性（self 定义），只有少数需要全局共享的才用类属性。

Q6
实例方法、类方法、静态方法的区别？如何选择？
进阶
+
类型装饰器首参使用场景

Q7
描述 open() 函数的参数及其含义。
基础
+

open(file, mode='r', encoding=None)

  • file：要操作的文件路径，可以是相对路径（./、../）或绝对路径（C:/、/usr/...）
  • mode：打开模式
    • 'r' — 只读（read），文件不存在会报错（默认）

Q8
为什么推荐使用 with 语句操作文件？
进阶
+

with open(...) as f: 是 Python 操作文件的最佳实践。

优点：

  • 自动关闭文件，不需要手动写 f.close()
  • 即使代码块中发生异常，也能保证文件被关闭
  • 代码更简洁清晰，可读性强

对比：

# ❌ 传统写法：异常时不会关闭文件 f = open('a.txt') data = f.read() # 这里如果报错，f 不会关闭 f.close() # ✅ with 写法：自动关闭 with open('a.txt') as f: data = f.read() # 出了 with 缩进，f 自动关闭
Q9
下面代码会输出什么？为什么？
陷阱
+
class Tool: count = 0 def __init__(self, name): self.name = name self.count += 1 # 注意这行 t1 = Tool('锤子') t2 = Tool('扳手') print(Tool.count) # ? print(t1.count) # ?

答案：Tool.count 输出 0，t1.count 输出 1。

原因：self.count += 1 等价于 self.count = self.count + 1。第一次执行时，self.count 找不到实例属性，找到类属性 Tool.count = 0，然后给实例自己创建了一个 count = 1（不是修改类属性！）。

正确写法：修改类属性必须用 类名.属性，即 Tool.count += 1。

Q10
用 'w' 模式打开一个已有的重要文件，没写入任何内容就 close() 了，文件会怎样？
陷阱
+

答案：文件内容会被清空。

原因：'w' 模式打开时立即清空原文件，不需要等 write() 调用。这是非常容易踩的坑！

f = open('important.txt', 'w') # 这一行就清空了！ f.close() # 关闭，文件已空

避坑技巧：

  • 读取用 'r'，追加用 'a'
  • 真的要覆盖前，先备份原文件
  • 操作重要文件用 'r+' 或 'x'（独占创建，存在则报错）
Q11
下面代码中，cat.eat() 会调用谁的 eat？
陷阱
+
class A: def eat(self): print('A.eat') class B(A): def eat(self): print('B.eat') class C(B): pass c = C() c.eat()

答案：输出 B.eat。

查找顺序（MRO）：

  1. 先在 C 中找 eat → 没找到
  2. 去父类 B 中找 → 找到，使用 B.eat
  3. 不再继续往上找了

Python 按 C → B → A → object 的顺序查找，找到就停。可以通过 C.__mro__ 查看完整顺序。

Q12
在自动化测试中，继承和多态如何应用？
场景
+

继承和多态在测试框架中无处不在：

  1. BasePage 基类：把所有页面共有的方法（click、input、wait）封装在 BasePage，各页面类（LoginPage、CartPage）继承复用。
  2. BaseTestCase 基类：在 unittest、pytest 中，所有测试类继承基类的 setUp/tearDown，统一处理浏览器启动、数据准备。
  3. 多浏览器适配（多态）：定义抽象 Driver 基类，ChromeDriver、FirefoxDriver 重写其方法。测试代码不变，传入不同浏览器对象即可。
  4. API 测试封装：基础 ApiClient 提供 get/post，业务 Api（如 UserApi）继承并添加业务方法。
  5. 断言扩展：自定义断言类继承 unittest.TestCase，扩展业务断言方法。

掌握继承和多态是从"会写脚本"进阶到"会做测试框架"的核心能力。
