1断言（Assert）进阶

断言让程序自动判断预期结果和实际结果是否相符。上节学了 assertEqual，本节重点讲 assertIn。

assertEqual —— 判断相等

self.assertEqual(预期结果, 实际结果) # 预期 == 实际 → 用例通过（不抛异常） # 预期 != 实际 → 抛出 AssertionError，用例标记 F self.assertEqual(10, 10) # ✅ 通过 self.assertEqual(10, 11) # ❌ 不通过

assertIn —— 判断包含

self.assertIn(预期结果, 实际结果) # 预期 in 实际 → 通过 # 预期 not in 实际 → 抛出 AssertionError self.assertIn('admin', '欢迎 admin 登录') # ✅ 包含，通过 self.assertIn('admin', '欢迎 adminnnnnn 登录') # ✅ 包含，通过 self.assertIn('admin', '欢迎 adddddmin 登录') # ❌ 不包含，不通过
💡 什么时候用 assertIn？
当接口返回的是一个长字符串（如 HTML 页面、JSON 字符串），只需要验证某个关键词是否在结果中出现时用 assertIn。
例：验证登录成功后页面包含"欢迎" → assertIn('欢迎', response.text)

完整断言方法一览

方法通过条件典型场景
assertEqual(a, b)a == b验证函数返回值，最常用
assertNotEqual(a, b)a != b验证结果不相等
assertIn(a, b)a in b验证关键词在响应中
assertNotIn(a, b)a not in b验证不包含
assertTrue(x)bool(x) is True验证条件为真
assertFalse(x)bool(x) is False验证条件为假
assertIsNone(x)x is None验证返回 None
assertIsNotNone(x)x is not None验证不为 None

2参数化（parameterized）

参数化：通过参数传递数据，实现数据和脚本分离。多组数据测试同一功能，只需写一个测试方法。

⚠️ 前提：安装 parameterized 插件
unittest 本身不支持参数化，需要安装第三方插件：
pip install parameterized
或国内镜像：pip install -i https://pypi.douban.com/simple/ parameterized

使用步骤（5 步）

  1. 导包：from parameterized import parameterized
  2. 修改测试方法，将测试数据改为变量参数
  3. 组织测试数据：格式 [(), (), ()]，一个元组是一组数据
  4. 在测试方法上方加装饰器：@parameterized.expand(测试数据)
  5. 运行（直接 TestCase 或 Suite 都可以）

示例一：直接定义数据列表

import unittest from parameterized import parameterized def add(a, b): return a + b # 每个元组是一组测试数据 (a, b, 期望结果) data = [(1, 1, 2), (1, 2, 3), (2, 3, 5), (4, 5, 9)] class TestAdd(unittest.TestCase): @parameterized.expand(data) # 装饰器 def test_add(self, a, b, expect): # 参数对应元组的每个值 print(f'a:{a}, b:{b}, expect:{expect}') self.assertEqual(expect, add(a, b)) if __name__ == '__main__': unittest.main()
🎯 参数化后方法名规律
parameterized 会自动为每组数据生成独立的测试方法名，如：
test_add_0、test_add_1、test_add_2…
这样每组数据独立统计通过/失败，互不影响。

示例二：从 JSON 文件读取数据（数组格式）

# add_data.json（JSON 数组格式） [ [1, 1, 2], [1, 2, 3], [10, 20, 30] ]
import json def build_add_data(): with open('add_data.json') as f: data = json.load(f) # [[], [], []] → parameterized 自动转元组 return data # 使用时：@parameterized.expand(build_add_data())

示例三：从 JSON 文件读取数据（对象格式）

# login_data.json（JSON 对象数组格式） [ {"desc": "正确用户名密码", "username": "admin", "password": "123456", "expect": "登录成功"}, {"desc": "错误用户名", "username": "root", "password": "123456", "expect": "登录失败"} ]
def build_login_data(): with open('data/login_data.json', encoding='utf-8') as f: data_list = json.load(f) # [{}, {}] → [(), ()] new_list = [] for data in data_list: username = data.get('username') password = data.get('password') expect = data.get('expect') new_list.append((username, password, expect)) return new_list # 简洁写法（dict 值全部需要时） def build_data_v2(): with open('data/login_data.json', encoding='utf-8') as f: data_list = json.load(f) return [tuple(d.values()) for d in data_list]

3跳过（Skip）

对于未完成或不满足测试条件的测试方法，可以设置为跳过，不执行。

两种跳过方式

@skip 无条件跳过

直接跳过，不管任何条件

@unittest.skip('原因') def test_method(self): pass

@skipIf 条件跳过

条件为 True 时跳过

@unittest.skipIf(条件, '原因') def test_method(self): pass

完整示例

import unittest version = 29 class TestSkip(unittest.TestCase): @unittest.skip('没什么原因，就是不想执行') def test_1(self): print('方法一') # ⏭ 跳过，不会执行 @unittest.skipIf(version >= 30, '版本号>=30 不执行') def test_2(self): print('方法二') # version=29 < 30，条件为 False，正常执行 def test_3(self): print('方法三') # 正常执行
💡 执行结果中跳过的表示
跳过的用例显示为 s（小写），例如 .s. 表示：第一个通过、第二个跳过、第三个通过。
跳过不算失败，最终统计 OK (skipped=1)。

4生成测试报告（HTMLTestReport）

使用第三方报告模板 HTMLTestReport 生成漂亮的 HTML 测试报告，本质是一个自定义的 TestRunner。

安装

pip install HTMLTestReport # 或国内镜像 pip install -i https://pypi.douban.com/simple/ HTMLTestReport

使用步骤（4 步）

  1. 导包：import unittest 和 from htmltestreport import HTMLTestReport
  2. 组装用例（套件 or Loader）
  3. 用 HTMLTestReport 的 runner 执行套件（替代 TextTestRunner）
  4. 查看生成的 HTML 报告文件
import unittest from htmltestreport import HTMLTestReport from case.test_login import TestLogin suite = unittest.TestSuite() suite.addTest(unittest.makeSuite(TestLogin)) # HTMLTestReport(报告路径.html, 报告标题, 描述) runner = HTMLTestReport('report/login_report.html', '登录测试报告', 'V1.0') runner.run(suite)
✅ 报告内容
HTML 报告包含：测试用例列表、通过/失败/跳过数量统计、每个用例的详细结果、失败用例的错误信息，可发送给 PM 或开发查看。

5绝对路径（os.path）

在分目录的项目中，使用相对路径可能因运行目录不同而找不到文件，推荐使用绝对路径。

关键知识点

语法含义
__file__特殊变量，表示当前代码文件名（路径）
os.path.abspath(path)获取绝对路径（补全完整路径）
os.path.dirname(path)获取路径的目录部分（去掉文件名）
os.path.join(a, b)路径拼接（跨平台安全）

在项目根目录创建 app.py（配置文件）

# app.py（放在项目根目录） import os # 获取当前文件的目录 = 项目根目录 BASE_DIR = os.path.dirname(__file__) # 或更严谨的写法（处理符号链接） BASE_DIR = os.path.dirname(os.path.abspath(__file__))

在其他文件中使用绝对路径

# read_data.py from app import BASE_DIR import json def build_login_data(): # 用 BASE_DIR 拼接完整路径，不受运行目录影响 path = BASE_DIR + '/data/login_data.json' with open(path, encoding='utf-8') as f: data_list = json.load(f) ... return new_list

6完整项目结构

完整的自动化测试项目推荐目录结构：

project/ ← 项目根目录 ├── app.py ← 配置文件，定义 BASE_DIR ├── tools.py ← 被测功能代码（login、add 等） ├── case/ ← 所有测试用例 │ └── test_login.py ← 用例代码（含 @parameterized） ├── common/ ← 公共模块 │ └── read_data.py ← 读取 JSON 数据的函数 ├── data/ ← 测试数据 │ └── login_data.json ← JSON 格式的测试用例数据 ├── report/ ← 测试报告输出目录 │ └── login_report.html ← 生成的 HTML 报告 └── run.py ← 主运行文件（Suite + HTMLTestReport）

run.py 完整代码

import unittest from app import BASE_DIR from htmltestreport import HTMLTestReport from case.test_login import TestLogin suite = unittest.TestSuite() suite.addTest(unittest.makeSuite(TestLogin)) runner = HTMLTestReport( BASE_DIR + '/report/login_report.html', '登录功能测试报告', 'V1.0' ) runner.run(suite)

完整用例代码 case/test_login.py

import unittest from parameterized import parameterized from tools import login from common.read_data import build_login_data class TestLogin(unittest.TestCase): @parameterized.expand(build_login_data()) def test_login(self, username, password, expect): print(f'username:{username}, pwd:{password}, expect:{expect}') self.assertEqual(expect, login(username, password))

1assertEqual vs assertIn 对比

⚖️ assertEqual 精确匹配

# 适合返回值完全可知时 self.assertEqual('登录成功', login('admin', '123456')) # '登录成功' == 实际返回值

适合：函数返回固定字符串、数字、布尔值

🔍 assertIn 包含匹配

# 适合返回值是大段文本时 self.assertIn('欢迎', response.text) # '欢迎' in '...欢迎 admin...'

适合：接口响应、HTML 页面、日志内容

3跳过装饰器对比

装饰器跳过时机使用场景
@unittest.skip(reason)无条件跳过功能未完成、临时禁用
@unittest.skipIf(cond, reason)条件为 True 时跳过特定版本/环境才执行
@unittest.skipUnless(cond, reason)条件为 False 时跳过仅在满足条件时执行
# skipIf: 条件为 True → 跳过 @unittest.skipIf(version >= 30, '版本>=30 跳过') # version=29 → 不跳 @unittest.skipIf(version >= 20, '版本>=20 跳过') # version=29 → 跳过 # skipUnless: 条件为 False → 跳过 @unittest.skipUnless(version >= 30, '版本不够跳过') # version=29 → 跳过

5绝对路径原理

📁 __file__ → abspath → dirname = BASE_DIR
import os # 假设 app.py 在 /Users/tester/project/app.py __file__ # 'app.py' 或相对路径 os.path.abspath(__file__) # '/Users/tester/project/app.py' ← 完整路径 os.path.dirname(...) # '/Users/tester/project' ← 目录名 BASE_DIR = os.path.dirname(__file__) # 拼接： data_path = BASE_DIR + '/data/login_data.json' # '/Users/tester/project/data/login_data.json'
⚠️ 为什么不用相对路径？
在 run.py 中执行时，Python 的工作目录是运行命令的目录，不一定是 project 根目录。用相对路径会导致 FileNotFoundError。BASE_DIR 固定是 app.py 所在目录，永远正确。

Q1
assertEqual 和 assertIn 有什么区别？分别在什么场景下使用？
基础
+

assertEqual(a, b)：判断 a == b，要求精确相等。适合函数返回值是固定字符串、数字、布尔值的场景。

assertIn(a, b)：判断 a in b，验证包含关系。适合返回值是大段文本、响应内容包含某个关键词的场景。

测试示例：

  • 登录函数返回 '登录成功' → 用 assertEqual('登录成功', result)
  • UI 页面返回 HTML，验证含"欢迎" → 用 assertIn('欢迎', response.text)
  • 接口响应 JSON 字符串，验证含 "success" → 用 assertIn('success', response.text)
Q2
什么是参数化？为什么要参数化？
基础
+

参数化：通过参数传递数据，实现测试数据和测试脚本分离。同一个测试方法可以用多组数据执行多次。

为什么要参数化：

  • 避免重复代码：4 组数据写 4 个方法 → 参数化写 1 个方法
  • 数据驱动：测试数据存 JSON 文件，脚本不变；新增/修改数据只改 JSON
  • 独立统计：每组数据生成独立用例，一组失败不影响其他
  • 可维护性强：非技术人员可以维护测试数据（JSON 文件）
Q3
如何使用 parameterized？写出完整的使用步骤。
基础
+
  1. 安装：pip install parameterized
  2. 导包：from parameterized import parameterized
  3. 组织数据：data = [(a1,b1,e1), (a2,b2,e2), ...]
  4. 装饰器：在方法上方加 @parameterized.expand(data)
  5. 修改方法：参数与元组元素一一对应 def test_x(self, a, b, expect):
  6. 运行即可
Q4
读取 JSON 测试数据时，数组格式和对象格式的处理有什么不同？
进阶
+

数组格式 [[a,b,e], ...]：json.load 直接返回嵌套列表，parameterized 可直接接受，不用转换：

data = json.load(f) # [[1,1,2], [1,2,3], ...] # 直接传给 @parameterized.expand(data)

对象格式 [{"username":..., "expect":...}, ...]：需要手动转换为元组列表：

new_list = [(d['username'], d['password'], d['expect']) for d in data_list]

优势对比：对象格式更清晰（有字段名），推荐；数组格式更简洁，适合简单数据。

Q5
skip 和 skipIf 的区别？
基础
+
  • @unittest.skip(reason)：无条件跳过，直接标记该方法不执行
  • @unittest.skipIf(condition, reason)：条件为 True 时跳过，False 时正常执行
  • @unittest.skipUnless(condition, reason)：条件为 False 时跳过（与 skipIf 相反）

常见场景：

  • 功能未完成 → @skip
  • 在低版本不需要执行某功能 → @skipIf(version < 30, '旧版本跳过')
  • 只在 Windows 执行 → @skipIf(not sys.platform.startswith('win'), '非 Windows')

跳过的用例显示为 s，最终统计 OK (skipped=N)，不算失败。

Q7
为什么要用绝对路径？如何获取项目根目录？
进阶
+

为什么：在分目录项目中，从不同位置运行脚本时，相对路径的基准目录不同，会导致 FileNotFoundError。绝对路径固定从项目根目录出发，不受运行目录影响。

获取方式：在项目根目录创建 app.py：

import os BASE_DIR = os.path.dirname(__file__)

其他文件通过 from app import BASE_DIR 使用，拼接路径：

path = BASE_DIR + '/data/login_data.json'

__file__ 是什么：Python 的特殊变量，表示当前代码文件名（或路径）。os.path.dirname 去掉文件名，只保留目录。

Q8
参数化测试中，每组数据的测试方法名是什么格式？
进阶
+

parameterized 会根据数据自动生成方法名，格式为：

原方法名_序号_数据内容，例如 test_login_0、test_login_1、test_login_2...

每组数据独立作为一个测试方法，相互独立，一组失败不影响其他组。

在报告中可以清楚看到哪组数据导致了失败，便于定位问题。

Q9
下面的断言代码会通过吗？为什么？
陷阱
+
self.assertIn('admin', '欢迎 adminnnnnn 登录') # ① ? self.assertIn('admin', '欢迎 adddddmin 登录') # ② ?

答案：① 通过，② 不通过

解析：assertIn 判断的是字符串包含，相当于 Python 的 in 运算符：

  • ① 'admin' in '欢迎 adminnnnnn 登录' → True（字符串中有 admin 这个子串）
  • ② 'admin' in '欢迎 adddddmin 登录' → False（adddddmin 不包含连续的 admin 子串）

不是"模糊匹配"，而是严格的子字符串包含。

Q10
skipIf 和 skipUnless 的关系？
陷阱
+

两者是互补关系：

  • @skipIf(cond, reason)：条件为 True → 跳过，False → 执行
  • @skipUnless(cond, reason)：条件为 False → 跳过，True → 执行

等价关系：skipUnless(cond) ≡ skipIf(not cond)

例：

# 两种写法效果等同 @unittest.skipIf(version < 30, '版本不够') @unittest.skipUnless(version >= 30, '版本不够')

选哪个取决于哪种表述更自然可读。

Q11
如果 JSON 数据文件中有 desc 字段，参数化时不需要 desc，如何处理？
进阶
+

在 build_data 函数中，只取需要的字段，不要的字段（如 desc）直接跳过：

def build_login_data(): with open('login_data.json') as f: data_list = json.load(f) return [ (d['username'], d['password'], d['expect']) # 不要 desc for d in data_list ]

这样测试方法签名是 def test_login(self, username, password, expect)，与数据精确对应。

如果全部值都需要，可用 tuple(d.values())，但要确保 JSON 键的顺序与方法参数顺序一致。
