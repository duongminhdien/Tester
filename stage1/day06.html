🗺️Stage 1 知识地图

下面是 Day 01-05 的核心知识点速查表，可作为考前复习清单：

● Day 01 · 测试基础

核心概念：软件测试定义、目的（发现缺陷不是证明无错）、Verification（做对了吗）vs Validation（做的是对东西吗）
SDLC vs STLC：STLC 是 SDLC 的子集，专注测试活动
分类：按阶段（单元→集成→系统→验收）/ 按代码可见度（黑/灰/白盒）/ 按执行方式（手动/自动化）
ISO 25010：8 大质量维度（功能、性能、兼容、易用、安全、可靠、可维护、可移植）
测试用例 8 要素：编号、标题、模块、前置条件、优先级、步骤、数据、预期结果
测试流程 6 步：需求分析 → 计划 → 用例设计 → 执行 → 缺陷管理 → 报告

● Day 02 · 用例设计方法

等价类划分：有效类 + 无效类，每类取代表值，减少用例数量
边界值分析：上点 / 离点 / 内点；"开内闭外"原则 — 闭区间的离点在外，开区间的离点在内
7点 vs 5点：简化策略保留上点(2)+内点(1)+离点(2)，简化掉另外2个离点
判定表 4 步：列条件桩 → 列动作桩 → 填写规则 → 简化合并
条件 ≥ 4 个：判定表不适用，改用正交法
状态转换：合法路径 + 非法路径都要测
错误推测：补充性方法，根据经验找历史易错点

● Day 03 · 缺陷管理

Bug 5 标准：未实现 / 实现错误 / 多余功能 / 未达需求 / 难以理解
生命周期 7 状态：New → Assigned → Open → Fixed → Retest → Closed/Reopened
Bug 6 核心要素：标题、严重程度、优先级、复现步骤、预期/实际、附件
严重程度 S1-S4：致命（系统崩溃）→ 严重（功能不可用）→ 一般（功能错误）→ 轻微（UI/文字）
优先级 P0-P3：立即修复 → 高 → 中 → 低
标题格式："【模块】+ 操作 + 预期 vs 实际" 五要素清晰
工具：ZenTao / Jira / Bugzilla

● Day 04 · HTML 基础与前端测试

三大核心：HTML 结构 / CSS 样式 / JS 行为
骨架：<!DOCTYPE html> / <html> / <head> (含 meta charset) / <body>
8 类常用标签：标题 h1-h6 / 段落 p / 图片 img / 链接 a / 列表 ul-ol-li / 表格 table / 表单 form / 容器 div-span
input 类型：text / password / radio / checkbox / submit / file / date / number / email
GET vs POST：GET 参数在 URL（不安全）/ POST 参数在 body / GET 有长度限制 / GET 可缓存可收藏
路径：相对路径（./../）/ 绝对路径（/根目录开始 或 http://）

● Day 05 · 黑马头条实战

登录模块测试要点：账号长度边界 / 密码规则 / 滑块验证 / 错误次数锁定 / 记住密码 cookie
滑块验证逻辑：误差范围内通过 / 失败计数 / 达到上限锁定
发布文章测试要点：标题/正文/封面/分类等字段验证 / 富文本编辑器 / 草稿箱 / 发布权限
用例覆盖：正常流程 + 异常流程 + 边界值 + 等价类组合
实战思路：从业务整体到单功能（先测端到端流程，再测细节字段）
