接口的本质定义
01 — API 是什么
API（Application Programming Interface，应用程序接口）是程序之间约定好的通信方式。

生活类比：
• 餐厅的菜单 = API 文档（告诉你能点什么）
• 你点菜 = 发送请求（Request）
• 厨房做菜返回 = 服务器响应（Response）
• 你只管点菜，不需要知道厨房怎么做 = 黑盒测试
📌 接口测试本质：不通过 UI 界面，直接向服务器发送 HTTP 请求，验证响应结果是否符合预期。
内部接口 vs 外部接口
02 — 接口分类（按位置）
类型定义示例测试重点
内部接口系统各子模块之间的接口，或提供给内部系统使用的接口订单模块调用库存模块参数传递、数据一致性
外部接口①被测系统调用外部第三方接口调用微信支付、短信服务容错处理、超时
外部接口②系统对外提供的接口（供外部调用）提供给合作商的开放API鉴权、权限控制、限流
接口测试的 6 大检查重点
① 参数正确性
传入正确/错误参数，结果是否符合预期
② 功能正确性
接口业务逻辑是否实现正确
③ 输出结果
返回的数据结构、类型、值是否正确
④ 异常容错
空值、类型错误、超长参数的处理
⑤ 权限控制
鉴权是否生效、越权访问是否被拦截
⑥ 限流/分页
调用次数限制、分页逻辑是否正确
三大接口架构
📋
SOAP 架构
SOAP
基于 XML 规范，WebService 协议

• 接口地址以 ?wsdl 结尾
• 结构严格，报文体积大
• 企业级系统、银行多用
• Postman ✅
⚡
RESTful 架构
REST
基于 JSON + HTTP，最主流

• 用 HTTP 方法表达操作意图
• 轻量、易读、开发效率高
• 互联网应用标配
• Postman ✅ JMeter ✅
🔌
RPC 架构
RPC
基于 Dubbo/Thrift 协议
SpringCloud 微服务底层

• 全双工，基于 TCP
• 高性能，微服务内部常用
• Postman ❌ JMeter 需插件
🔄
WebSocket
WS
基于 TCP，全双工长连接

• 服务器可主动推送
• 聊天、实时推送场景
• Postman ❌ 不适用
💡 记忆口诀：基于 HTTP 的（REST、GraphQL、SOAP）适合 Postman；基于 TCP 全双工的（WebSocket、RPC）不适合 Postman。

方法操作示例接口幂等性Postman Body
GET查询/获取资源GET /users → 用户列表✅ 是无 Body，用 Query Params
POST新增/创建资源POST /users → 创建用户❌ 否Body（JSON/form）

PATCH部分更新资源PATCH /users/1 → 改昵称✅ 是Body（JSON）只传改的字段
DELETE删除资源DELETE /users/1 → 删用户✅ 是通常无 Body
⚠️ PUT vs PATCH：PUT 需要传所有字段（缺少的字段会被置空/默认值）；PATCH 只传需要修改的字段。改昵称用 PATCH 更合适。
